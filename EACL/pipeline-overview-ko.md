## 용어 (이 문서 전체에서 이 표현만 쓴다)

| 용어 | 뜻 |
|---|---|
| **EISM 5축** | 사건 색인 모델(Event-Indexing Model)의 다섯 지표 — 주인공 / 공간 / 시간 / 인과 / 의도 |
| **앵커 라벨** | LLM이 문장마다 붙인 5축 상태 라벨. 분절기 학습의 지도신호 |
| **리셋** | 축의 상태가 직전 문장 대비 바뀐 것(0/1). 판정은 LLM이 아니라 코드가 한다 |
| **동시 리셋 수** | 한 문장 전이에서 리셋된 축의 개수(0~5) |
| **M1-CosDrift** | 인접 문장 임베딩 코사인 거리 기반 규칙형 경계 탐지기. 학습 없음 |
| **M2-MonoLAM** | 단일 잠재 + 벡터 양자화 잠재행동모델. 앵커 없는 자기지도. 실패 |
| **M3-S5** | LLM 기반 5축 상태 추출기. 앵커 라벨 공급원이자 Phase 0 측정기 |
| **M4-MonoAnchor** | 단일 잠재 + 앵커. M5의 통제군 |
| **M5-FactoredSlot** | 5개 부분공간(슬롯) + 축별 dynamics + 앵커. 본 방법 |
| **B1-BayesSurprise** | GPT-2 기반 베이지안 서프라이즈 경계 탐지기(Kumar 2023). 스칼라 베이스라인 |
| **DTS Score** | `0.5·F1 + 0.25·(1−Pk) + 0.25·(1−WindowDiff)`. 전 실험의 주지표 |
| **deployable 평가** | 분절기가 경계 개수를 스스로 정하는 조건. 정답 경계 수를 주지 않는다 |
| **적응 임계** | 신호의 누적 평균 + 1 표준편차를 넘으면 경계. 과거만 사용 |
| **dev 3편 / 시험지** | 열람 가능한 연습 데이터(Pieman·Tunnel·Monkey) / 봉인된 held-out 3편 |

# 1. 앵커 코퍼스 1만편 구축

**역할.** M4~M7의 학습 지도신호 공급 전용. 모든 레코드의 경계 라벨이 0이며 **성능 평가에 쓰지 않는다.**
**필요성의 근거.** M2-MonoLAM은 앵커 없이 1,876만 인접쌍으로 학습했고, 데이터를 키울수록 오히려
나빠졌다(0.333 → 0.314 → 0.231). 5축을 명시적으로 강제하지 않으면 표현이 내용으로 붕괴한다.

## 1.1 데이터 수집 및 전처리

**결과: 10,598편 · 2,777,561 문장 전이 · 718MB.**

| 구성요소 | 사양 | 결과 |
|---|---|---|
| 원천 | Project Gutenberg 영어 단편 | 권 3,209 → 편 26,252 |
| 권→편 분할 | 목차·제목 헤딩 기반 | 편 단위 문서 확보 |
| 길이 필터 | 30~700 문장 | — |
| 작가당 상한 | 16편 | 후보 10,700편 |
| 편 내부 정리 | 서지·전사자 주석 등 제거. **편 분할 이후** 수행 | — |
| 격리 | QC 12편 · dev 3편 · 시험지 제외 | 누출 0 |
| 라벨링 손실 | 컨텍스트 초과 28 · 반복 붕괴 74 | −0.95% → **10,598편** |

- **장르 = 서사 픽션 단일.** 시나리오(대사 전용) 혼합은 배제했다 — M5 대 M4 대조를 흐리기 때문이다.
  대신 편별 **대사 밀도**를 메타데이터로 남겨 사후 층화가 가능하다.
- 문장 분할기는 Phase 0 동결본을 그대로 사용.

**한계**
- 작가 편중: 편수 +33%인데 작가 수는 +7%(2,141 → 2,298). 증가분이 소수 다작 작가에 몰렸다.
- SF 비중 18.8%. 장르는 서사 픽션 단일이므로 대화·비서사 도메인은 학습 범위 밖.
- 경계 정답이 없다. 성능 수치는 정답이 있는 dev 3편에서만 산출한다.

## 1.2 라벨링

**결과: 라벨러 = Qwen3.6-35B-A3B(추론 비활성) 동결 유지. 후보 교체 없음.**

| 구성요소 | 사양 |
|---|---|
| 라벨러 | Qwen3.6-35B-A3B, FP8, 추론(thinking) 비활성 |
| 프롬프트 | 5축 추출 v3.1 (동결) |
| 디코딩 | temperature 0, 배치 20, 시드 = 20260711 + 축 인덱스 |
| 표본 수 | 문장·축당 단일 표본 |
| 서빙 | vLLM 0.25.1, 텐서 병렬 1, 접두 캐시 사용 |
| 규모 | A100 80GB × 20, 호출 696,590건, 7시간 34분, 약 $95, 실패 0 |

**후보 비교 (dev 3편, deployable DTS Score, 3회 반복 평균 ± 표준편차)**

| 라벨러 | Pieman | Tunnel | Monkey | 평균 |
|---|---|---|---|---|
| Qwen3.6-35B-A3B (현행) | 0.424 ±0.018 | 0.410 ±0.012 | 0.314 ±0.032 | **0.382** |
| gpt-oss-120b | 0.515 ±0.056 | 0.327 ±0.023 | 0.296 ±0.036 | **0.380** |

- 사전 등록한 채택 조건은 **평균 +0.03 이상이면서 3편 중 2편 이상 하락 없음**이었다.
  실측은 **−0.003 · 무하락 1편**으로 미달 → **동결 유지, 앵커 재생성 없음.**
- 평균 동률은 상쇄의 결과다. 문서별 차이가 +0.091 / −0.082 / −0.017로 갈리며,
  **두 라벨러가 잘하는 문서가 서로 다르다.**
- **해석 한계 — 추론 조건이 비대칭이다.** Qwen은 추론을 완전히 끌 수 있지만 gpt-oss는 끄는 스위치가
  없어 최저 강도로 켠 채 비교했다. 이 과제에서 추론은 점수를 떨어뜨린다는 별도 근거가 있다
  (0.327 켬 대 0.364 끔). 따라서 이 수치는 **gpt-oss의 하한**이며, 말할 수 있는 것은
  "이 조건에서 우위 없음"까지다.
- 그 외 후보의 하드웨어·인터페이스 판정: DeepSeek 원본 FP8은 체크포인트 689.5GB로 보유 A100 4장
  (320GB)에 적재 불가 · 4비트 양자화본은 적재는 되나 희소 어텐션 커널이 Hopper 이상 전용이라 A100에서
  기동 실패 · MiniMax-M2.7과 gpt-oss는 추론 비활성 스위치 없음 · Gemma-4-26B-A4B만 Qwen과 동일한
  비활성 키를 지원해 교란 없는 비교가 가능하다.
  **후보끼리는 교란 종류가 달라 직접 비교하지 않고, 각각 현행 라벨러와만 비교한다.**

### 1.2.1 Stage 1 — 선택지 생성 (문서당 1회)

| 구성요소 | 사양 | 결과 |
|---|---|---|
| 입력 | 문서 전체 | — |
| 출력 | 등장인물 · 장소 · 목표의 **닫힌 목록** | Stage 2의 선택지가 된다 |
| 제약 | 경계·전환 관련 어휘를 프롬프트에서 배제 | Stage 2가 경계를 역추론하지 못하게 함 |

- **설계 의도:** 열린 서술 대신 문서 고유의 선택지를 먼저 만들고, 문장 판정은 그 안에서 고르게 한다.
  같은 대상을 문장마다 다른 표현으로 부르는 문제가 사라져 리셋 판정이 표현 변화가 아닌 상태 변화를 잡는다.
- **실패 모드:** 목록 배열에 길이 제한이 없어 탐욕 디코딩이 같은 값을 무한 반복하는 사례가 있었다
  (재현율 100%, 문서 길이와 무관). 상한을 걸면 중복으로 채워진 목록이 검증을 통과해버리므로,
  **상한을 걸지 않고 해당 문서를 제외**하는 쪽을 택했다(전체의 0.7%).
- **주의:** 추출기는 Stage 1 결과를 파일 단위로 캐시하며 **모델을 확인하지 않는다.**
  라벨러를 바꾸면 Stage 1부터 재생성해야 한다.

### 1.2.2 Stage 2 — 상태 판정 및 리셋 산출 (문장 단독, 축별 개별 호출)

| 구성요소 | 사양 |
|---|---|
| 입력 | 문장 1개 + Stage 1 목록 + 축별 고정 열거형 |
| 호출 단위 | **축마다 개별 호출** — 한 축의 판단이 다른 축으로 번지는 것을 차단 |
| 출력 | 축의 **절대 상태**(변화 여부가 아님) |
| 리셋 판정 | 직전 상태와 코드로 비교. LLM은 판정에 관여하지 않는다 |
| 느린 축 처리 | 공간·의도는 명시가 없으면 직전 값 유지(carry-forward) |
| 경계 규칙 | 동시 리셋 수 ≥ 3 |

**축별 리셋 발화율 (앵커 코퍼스 전량)**

| 축 | 발화율 | 판정 |
|---|---|---|
| 주인공 | 0.3049 | 정상 |
| 공간 | 0.1047 | 정상 |
| 시간 | 0.0213 | 가장 희소 |
| 인과 | **0.6950** | **포화 — 약축** |
| 의도 | 0.1140 | 정상 |
| **경계율(동시 리셋 ≥ 3)** | **0.0649** | 동시 리셋 수 분포: 0 = 17.6% · 1 = 48.0% · 2 = 27.9% · 3 = 5.8% · 4 = 0.7% · 5 ≈ 0% |

- 서빙 설정(텐서 병렬 차수, 접두 캐시)과 코퍼스 규모를 바꿔도 다섯 축 발화율이 ±0.01 안에서 일치했다.
  단 이는 **집계 분포의 일치이지 문장 단위 일치가 아니다.**
- **시간 축은 시제 조건을 제거한 뒤 확정됐다.** 시제 역전의 119건 중 103건이 오검출이었고,
  "시제 변화 ≠ 시간 지표 변화"는 EISM 조작화에 대한 결과로 보고한다.
- **인과 축은 조작화를 종결했다.** 관계형 5건, 상(aspect) 전이 1건, 의도 사슬 2건 등 총 8회 시도가
  모두 기준 미달이었다. 발화율 0.695는 사실상 상시 발화라 판별력이 없다.
  **약축으로 확정하되 축은 제거하지 않는다** — 5축 구조가 주장의 본체이기 때문이다.

## 1.3 라벨링 평가

두 축으로 검증한다. **하류 유용성**(dev 3편의 분절 점수)과 **라벨 자체의 정오**(사람 검수).
어느 하나로 대체되지 않는다.

### 1.3.1 dev 3편

**결과: deployable DTS Score 평균 0.382 (Pieman 0.424 / Tunnel 0.410 / Monkey 0.314).**

| 구성요소 | 사양 |
|---|---|
| 데이터 | Pieman 96문장/18경계 · Tunnel 504/18 · Monkey 408/30 (Michelmann 통일 gold) |
| 지표 | deployable DTS Score, 5축 전부, 동시 리셋 ≥ 3 |
| 반복 | 라벨러당 3회 — 배치 비결정성 때문. 평균과 표준편차를 함께 보고 |
| 비교군 | M1-CosDrift, B1-BayesSurprise, **B2/B3-LLM 직접 질의**, **인간 개별 주석자** |

- **모델 크기와 점수가 정렬되지 않는다.** 35B 라벨러가 GLM-4.5-Air(0.352), Qwen3-Next-80B(0.318),
  상용 프록시 모델(0.364)을 모두 앞섰다.
- **논문 중심 대조는 M3-S5 대 B1-BayesSurprise다** — 다축 리셋 대 스칼라 서프라이즈,
  즉 두 인지 이론의 대결이다. AUC 0.717 대 0.558(거의 우연 수준)이며,
  이 대조는 **Score와 AUC를 반드시 함께** 보고한다(임계 작동점 성분 때문).
  ⚠️ **이 AUC 쌍의 출처는 dev 3편이 아니라 Tier2 silver 7편 held-out(D-M12)이다.**
- **B1은 약화된 베이스라인이 아니다.** B1의 LM을 **M3-S5 라벨러와 동일한 Qwen3.6-35B-A3B**로 바꿔도
  문장 전이 AUC가 **0.517~0.529(우연 수준)**에 머문다 — 1.5B(GPT-2-XL, 0.533~0.563)의 23배인데
  오히려 내려갔다. dev-3 pooled Score는 0.2836 → 0.3238로 오르지만 그 이득은 순위력이 아니라
  **과분절 완화**(BOR 4.67배→2.78배)에서 온다. **스칼라 서프라이즈의 한계는 모델 용량이 아니라
  방법이다.** ⚠️ 실패는 **문장 접합 수준에 국한**된다 — 단어 해상도에서는 Kumar 원 결과가 재현된다.
- **"LLM에 그냥 물어보면?"의 답 = B2/B3.** Michelmann(B2)의 프롬프트를 B3(Panela)가 그대로 물려받았고,
  우리는 그 절차를 최신 모델로 돌렸다. dev 3편 오프라인 topline = GPT-4.1 **0.474**(reps=20),
  같은 조건을 문장 스트리밍으로 바꾸면 GPT-4.1 0.401 / GPT-5 0.391 / gpt-oss-120b 0.383으로,
  **LLM 호출이 0회인 M5(0.396)가 그 밴드 안에 들어온다.**

  **B3 절차를 어디까지 그대로 따랐나** (원 설계 = Born a Crime 세 챕터를 각 1,500단어로 잘라
  문단 없이 한 덩어리로 인쇄 → 젊은 성인 20명이 읽으며 경계 표시 + 즉시 구술 회상)

  | 항목 | B3 원 설계 | 우리 | 같은가 |
  |---|---|---|---|
  | 서식 | 문단 구분 없이 한 덩어리로 인쇄 | 연속 공백을 전부 공백 1개로 정규화해 한 덩어리 | ✅ |
  | 프롬프트 | B2의 zero-shot 문구 그대로 | **한 글자도 바꾸지 않음** | ✅ |
  | 반복 | 20회 | 20회, 다수결 합의(과반 run이 찍은 전이만 경계) | ✅ |
  | 경계 주체 | **사람 20명** | **GPT-4.1 20회** | ❌ 다름 |
  | 회상 과제 | 있음(마이크 구술) | 없음 — 경계만 | ❌ 없음 |
  | 자극 분량 | 챕터당 1,500단어로 절단 | **절단하지 않음**(최대 4,623단어) | ❌ 3배 이상 |
  | 모델 | `gpt-4` | **GPT-4.1** | ❌ 승계 |

  - **문단 제거는 재현 충실도이자 파싱 전제다.** 프롬프트가 "사건이 바뀔 때마다 새 줄을 시작하라"이므로
    입력에 줄바꿈이 남아 있으면 **모델이 넣은 경계와 원문의 줄바꿈을 구별할 수 없다.**
  - 🔴 **자극이 길어서 모델을 바꿔야 했다.** 원 `gpt-4`는 8k 컨텍스트라 전문 verbatim 복사가
    기계적으로 잘린다(실측: 4,623단어 문서에서 절단). 인용은

# 2. 온라인 사건 분절기 학습 (M5-FactoredSlot)

**목표.** (1) EISM 5축이 계산 모델로 구현했을 때 인간 사건 경계를 설명하는가, 그리고 어디서 실패하는가.
(2) 추론 시 LLM 호출 없이 문장 스트리밍으로 실시간 분절이 되는가.
**핵심 대조는 M5 대 M4다.** 앵커는 동일하고 차이는 표현 구조 하나뿐이므로, 그 차이가 곧 분리의 기여다.
2.1~2.4는 전부 우리가 만든 대조군이고, **문헌의 방법과의 비교는 §2.5**에 따로 둔다.

## 2.1 학습 방식

### 2.1.1 고정된 인코더 + 축 5개

**결과: 정렬 통과 — 요인화 이득 +0.150 (사전 검증 단계의 3.6배). 분절 성능 개선은 없음.**

| 구성요소 | 사양 |
|---|---|
| 인코더 | `paraphrase-multilingual-mpnet-base-v2`, 768차원, L2 정규화, **동결** |
| 학습 파라미터 | 143만 (동결된 2.78억 위에 얹은 모듈만) |
| 슬롯 | 5개, 축별 고정 키(EntNet 방식), 슬롯 차원 128 |
| dynamics | **축별 개별** — 축마다 자기 전이 함수 |
| 예측 공간 | **슬롯 고유 공간** — 인과 축의 잦은 변동이 공간·시간 축으로 새지 않는다 |
| 학습 데이터 | 앵커 코퍼스 10,069편 학습 / 529편 검증 (278만 문장) |
| 최적화 | 8 epoch, 배치 32, 학습률 3e-4 |

- **인코더를 동결하는 이유:** M1부터 M7까지 같은 인코더를 쓴다. 성능 차이가 표현 구조에서
  왔음을 보장하기 위한 조건이며, 파인튜닝이 아니다.
  ⚠️ **외부 베이스라인은 이 조건 밖이다** — B1은 자기회귀 LM 서프라이즈, B2/B3는 LLM 프롬프팅이라
  구조적으로 이 인코더를 공유할 수 없다. 그쪽은 §1.3.1의 모델 강건성 검사로 통제한다.
- **슬롯에 키를 심는 이유:** Slot Attention의 슬롯은 교환 가능해서 "이 슬롯이 주인공"이 저절로
  생기지 않는다. 비지도 분리는 원리적으로 불가능하다는 결과(Locatello 2019)와 M2의 실패가 같은 지점을
  가리킨다. 그래서 앵커로 담당 축을 지정한다.
- **설계 대비 미구현 부분이 있다.** 이종 예측 분포족, 지속성 사전(sticky-CRP), 우도비 스위칭,
  슬롯 고유 예측 공간을 4단계로 모두 붙여봤으나 **매 단계 리셋 확률 합보다 낮았다**
  (우도비 최고 AUC 0.6511 대 리셋 확률 합 0.7006). 스위칭 경로를 종결하고,
  논문 축을 **다축 동시 리셋 탐지**로 확정했다.
- **단일 잠재(M4)가 성능이 비슷해도 M5가 필요한 이유:** 단일 잠재는 어느 축이 리셋됐는지 읽을 수 없어
  동시 리셋 가설의 검정 자체가 불가능하다.

### 2.1.2 손실 함수

**결과: 양성 가중치 제거로 dev 3편 0.3617 → 0.3963 (+0.0346, 3개 시드 모두 개선).**

```
L = Σ_k α_k · [ L_변화,k + β · L_상태,k ] + γ · L_붕괴방지 + λ_예측 · L_예측
```

| 항 | 역할 | 설정 |
|---|---|---|
| `L_변화` | 축별 리셋 여부에 대한 이진 교차엔트로피. **주 항** | 축 가중치 α = [1.0, 0.5, 1.0, 0.4, 0.25] |
| `L_상태` | 축의 절대 상태 복원. 슬롯에 접지를 준다 | 보조 항(β = 0.25) |
| `L_붕괴방지` | 어떤 슬롯도 상수가 되지 않게 하는 정규화 | γ = 0.05, 분산 하한 0.1 |
| `L_예측` | 다음 상태 기대와 실측의 제곱거리. **라벨 없는 자기지도** | λ_예측 = 1.0 |

- **`L_예측`의 실제 식** (`src/hi_ontop/factored_slot.py:421–433`). 슬롯 k의 전이 함수가
  `ŝ_{t+1}^(k) = f_k(s_t^(k))`로 다음 상태를 예측하고, §2.1.1의 **슬롯 고유 공간**에서
  제곱거리를 잰다 — 전이마다 축에 대해 평균, 유효 전이에 대해 평균한다.
  ```
  L_예측 = 평균_t [ (1/5) · Σ_k ‖ ŝ_{t+1}^(k) − s_{t+1}^(k) ‖² ]
  ```
  코드에는 예측 슬롯들을 문장 임베딩으로 되돌려 `‖ẑ_{t+1} − z_{t+1}‖²`를 재는 관측공간
  변형(`--pred-space obs/both`, 코드 기본값)도 있고 **초기 런은 이 관측공간 조건이었다**
  (체크포인트 `M5_per_slot_seed*`). **현행 채택 계열은 전부 슬롯 공간**이다
  (`M5_per_slot_slot_*` — §2.1.2 결과 수치와 §2.2 이후가 모두 이 계열). 대조 항(contrastive)은 없다.
- **예측 타깃에 stop-gradient가 없다.** `s_{t+1}`로도 경사가 흐르므로 원리적으로 자명해(전 슬롯 상수)가
  가능하며, 이를 막는 것은 대조 항이 아니라 `γ · L_붕괴방지`(슬롯별 시간축 표준편차 하한)다.
- **`L_예측`은 표현을 만드는 신호이지 경계 규칙이 아니다.** 기본 설정에서 변화 head의 입력은
  `[s_{t-1}, s_t, s_t − s_{t-1}, s_t ⊙ s_{t-1}]`로 **예측오차를 쓰지 않는다**(잔차를 head 입력으로
  넣는 변형은 별도 옵션). 경계는 §2.2의 리셋 확률 합 + 적응 임계로 정한다.
  경계에서의 상태 리셋(스위칭)은 미구현이다(§2.1.1).

- **양성 가중치(pos_weight)를 전 축 1로 되돌린 것이 이번 개선의 전부다.**
  이전에는 클래스 불균형 보정으로 [2.28, 8.55, **30.0**, 1.00, 7.77]을 썼는데,
  가중 교차엔트로피의 최적해는 참 사후확률이 아니라 **가중된 사후확률**이다.
  그 결과 경계 신호가 1.74배(시간 축은 11.6배) 부풀려져 있었다.
  제거 후 신호는 **보정된 확률의 합 = 리셋 축 수의 기댓값**이 되어 해석 가능해졌다
  (dev 3편 1.074, 앵커 실측 1.240).
- 대화 도메인 검증셋은 −0.0079로, 사전에 잠근 비열등 허용폭(−0.047) 안이다.
- **축 가중치 α의 근거 기록이 없다.** 하드코딩 상수이며 미해결 항목이다.
  다만 α를 균등화해도 축별 확률이 거의 변하지 않음은 실측으로 확인했다.
- **인과 축은 양성 가중치를 제거해도 바뀌지 않는다**(0.529 → 0.527, 실제 0.695). 약축 확정과 일관.

**한계**
- 채택한 설정은 사전에 지정된 조건이 아니라 **2×2 중 dev 3편 최고점**이다.
  "확률을 건드리지 않는 최소 개입"이라는 논거가 있고 실측으로도 뒷받침되지만,
  **그 논거는 점수를 본 뒤에 정식화됐다.** 연습 데이터에 대한 선택 성분이 있다.

## 2.2 적응적 임계

**결과: 경계 개수를 스스로 정하는 온라인 규칙 확정. 다만 dev 3편에서 약 2.2배 과분절.**

```
경계  ⟺  s_t ≥ 누적평균(s_<t) + 1.0 × 누적표준편차(s_<t),      s_t = Σ_k P(리셋_k)
```

| 구성요소 | 사양 | 근거 |
|---|---|---|
| 신호 | 5축 리셋 확률의 합 | 축을 빼지 않는다 |
| 규칙 | 누적 평균 + 1σ | 문서 길이에 자동 적응 |
| 온라인성 | 과거 통계만 사용, 미래 미사용 | 실시간 배포 요건 |
| 정답 누출 | 정답 경계 개수 미사용 | deployable 요건 |
| 계수 1.0의 출처 | **SuperDialseg 공식 test(36,109 전이)** | TIAGE +0.071, dialseg711 +0.042 |

- **계수를 연습 데이터에서 고르지 않았다는 점이 이 규칙의 방어 지점이다.**
  dev 3편은 오히려 고정 임계를 지지했다(적응 0.3862 대 고정 0.3987).
- 누적 평균 + cσ 규칙은 **양의 아핀 변환에 불변**이므로, 양성 가중치 제거로 신호 스케일이
  1.88 → 1.07로 바뀌어도 계수를 다시 맞출 필요가 없다.
- **탈락한 대안**
  - 고정 분위수: dev 3편 점수는 더 높았으나(0.4191 대 0.3617) **출처가 무효**다.
    그 분위수는 폐기된 작동점(동시 리셋 ≥ 3)에서 유도된 값이라 순환이다.
  - Otsu: 무파라미터지만 **경계를 하나도 찍지 않는 하한(0.2790)과 같은 수준**(0.2831).
- **다른 임계 계열**(검색 청킹 실험에서 도입, 분절 트랙 이식은 별도 사전 등록 필요):
  지수가중이동평균 임계, 고정 경계율 임계, **최소·최대 길이 범위 제약 디코딩**
  (EM-LLM의 블록 크기 제약과 같은 구조이며 온라인이다).

## 2.3 5축은 어디서 기여하는가 — 교사 애블레이션과 결합 방식

**결과: 5축의 기여는 모델 구조가 아니라 라벨에 있다. 학생을 고정하고 교사만 바꾸면
무작위 대비 +0.087 / +0.140 · 스칼라 대비 +0.051 / +0.106 · 단일 축 대비 +0.030 / +0.076.
반대로 결합 함수를 바꾸는 것은 4종 전부 개선이 없다(Δ ≤ +0.003).**

## 2.4 외부 베이스라인 대조 — 채점기를 하나로 통일

**결과: 서사 dev 3편에서 M5가 외부 방법 7종을 전부 앞선다(최고 외부 방법 대비 +0.050).
다만 대화로 옮기면 학습 없는 코사인 드리프트에 밀린다 — 그리고 그 붕괴는 양방향이다.**

**왜 필요했나.** 2.3~2.4는 전부 우리가 만든 대조군이다. 문헌의 방법과 비교하려 했더니
우리 수치와 `methods/` 수치가 **서로 다른 채점기**에서 나온 것이었고, 같은 예측을 두 채점기로
재보니 차이가 0.045로 **재려는 효과(M5−M4 = 0.025)보다 컸다.** 그래서 전 방법을
**하나의 채점기**(SuperDialseg 공식 `dts_scoring`)로 다시 돌렸다.

| 구성요소 | 사양 |
|---|---|
| 채점기 | SuperDialseg 공식 1종으로 고정. 다른 채점기·논문 인용 수치는 이 표에 섞지 않는다 |
| 평가 모드 | deployable — **어떤 방법에도 정답 경계 개수를 주지 않는다** |
| 온라인성 | 오프라인 방법은 제외(경쟁 대상 아님). 외부 방법 4종도 스트리밍 적응판을 쓴다 |
| 작동점 | 외부 방법의 하이퍼는 **발표값과 1:1 대조 후 동결**. 우리가 정한 것만 선택셋에서 탐색 |
| 선택셋 | 서사 = dev 3편 · 대화 = superseg 검증 60대화. 🔴 **앵커는 쓰지 않는다**(사람 경계 라벨이 없다) |
| 원자료 | 전 방법이 전이별 0/1 예측을 파일로 덤프 — 언제든 재채점·감사 가능 |

### 2.4.1 전 지표표 — Score 하나로는 밀도와 신호가 섞인다 (2026-08-01)

> ⛔ **이 절의 표는 논문 main table 이 아니다 (2026-08-02, D-B62).** canonical =
> **`EACL/main_result.md`** — 무대 4개(dev-3 · **시험지** · DTS-3), M1·M4 제외,
> CSM 3판 병기, LLM 직접질의 편입. 아래는 그 이전 판이며 아래 항목이 갱신됐다:
> ① **시험지에서 M5 는 1위가 아니다**(GPT-4.1·TextTiling 아래 3위) ②
> **CSM 은 오프라인에서 논문을 재현한다** — 하한 근처인 것은 학습 실패가 아니라 온라인화 손실이다.

**결과: 지표를 6개로 펴니 Score 순위가 감추던 것이 드러난다 — 서사에서 외부 방법 3종은
"약한 신호"가 아니라 역신호(L1 < 1.0)다.**

| 지표 | 뜻 | 읽는 법 |
|---|---|---|
| Score | 0.5·F1 + 0.25·(1−Pk) + 0.25·(1−WD) | 주지표. 자명한 하한과 비교해야 의미가 있다 |
| BOR | 예측 경계 수 ÷ 정답 경계 수 | 1.0 = 밀도 일치 · >1 과분절 · <1 과소분절 |
| purity | 예측 구간이 정답 구간 하나에 얼마나 순수하게 담기나 | 과소분절에 벌점. 🔴 **잘게 쪼갤수록 자동으로 올라간다 — 단독 인용 금지** |
| coverage | 정답 구간이 예측 구간 하나에 얼마나 덮이나 | 과분절에 벌점 |
| F(p,c) | 두 값의 조화평균 | purity 단독의 착시를 즉시 드러낸다 |
| **L1** | P(경계\|예측) ÷ P(경계) = 표준 lift | **1.0 미만이면 역신호** — 찍은 자리가 오히려 정답일 확률이 낮다 |

**dev 3편 (서사) · 정답 66**

| 방법 | Score | BOR | purity | coverage | F(p,c) | L1 |

# 3. 다운스트림 검증

**질문.** 인간 사건 경계와 잘 맞는 분절이 실제 하류 과제에 유용한가.
**결과: 두 과제 모두 해당 과제의 기존 방법을 유의하게 넘지 못했다.** 아래는 그대로 적은 것이다.

## 3.1 EM-LLM — 장문맥 기억 (LongBench / ∞-Bench)

**결과: 최고 조건이 기준선 대비 +0.06 (95% CI [−0.32, +0.43]) — 구분되지 않음.**

| 구성요소 | 사양 |
|---|---|
| 기반 모델 | Llama-3.1-8B-Instruct |
| 평가 | LongBench 영어 15개 과제 3,550문항, 공식 채점기. ∞-Bench 2,653문항 병행 |
| 교체 지점 | 분절 결과를 토큰 불리언 마스크로 주입. EM-LLM 내부 코드는 수정하지 않음 |
| 통일 조건 | 전 조건에서 유사도 기반 경계 보정을 끔 — 비교 공정성 확보 |

임의 분할 비율이 소수점 셋째 자리까지 일치하고 **차이는 "강제 절단 위치를 M5 점수 최댓값으로 고르는가,

**철회 기록.** 상류 dev 3편 +10% 개선이 하류에서 −0.70으로 나와 "상류 개선이 하류를 악화시킨다"로
정리했다가, 결과를 보기 전에 고정해 둔 판독 규칙(세 임계 규칙 모두 음수여야 체크포인트 효과)에 따라
나머지 두 규칙에서 +0.01 / −0.06이 나오자 **철회했다.** 부호가 섞이면 노이즈이거나 임계 규칙과의
상호작용이다. 단일 조건 결과는 조건을 바꿔 재현되기 전까지 발견이 아니며, 이 프로그램에서 세 번 확인됐다.

**선택 지위.** LongBench에는 dev/test 분리가 없어 공식 test 전량을 매 조건 채점했다.
그러나 선택은 모두 상류에서 일어났다 — 체크포인트는 dev 3편, 임계 계수는 SuperDialseg 공식 test,
고정 분위수는 앵커 교차검증, 지수가중이동평균 폭은 밀도 매칭(점수 비열람).
**하류는 확인용이며, 전 조건을 보고하고 최고만 고르지 않는다.**

**부수 사항.** 재현을 위해 EM-LLM 저장소 결함 3건을 수정해야 했다 — 문장별 재토큰화로 인한
특수 토큰 중복 삽입, 분산 실행 시 동일 파일 동시 추가로 인한 레코드 손상, 회전 위치 임베딩 패치의
속성 참조 오류(현행 transformers에서 Llama-3.1 적재 자체가 불가).

## 3.2 LumberChunker / GutenQA — 검색 청킹

**결과: DCG@20 50.53 — 고정 크기 분할(50.35)과 동률, LLM 청커(56.22)에 −5.70으로 유의 미달.**

| 단계 | DCG@20 |
|---|---|
| 사전 등록 조건(고정 경계율) | 41.62 |
| 적응 임계 단독 | 47.79 |
| **+ 길이 정규화 → 보고 주값** | **50.53** |
| + 범위 제약 디코딩 | 50.86 |
| **고정 크기 재귀 분할 (목표선)** | **50.35** |
| **LumberChunker (LLM 청커)** | **56.22** |

- **판정: 동률이며 초과가 아니다.** 50.53 대 50.35 = +0.18 [−0.97, +1.36].
  사전 등록 기준은 "목표선 초과"였으므로 **미달**이다. 정직한 서술은
  **"이론 없는 고정 크기 분할과 통계적으로 구별되지 않는 수준에 도달했다"**이다.
- **길이 정규화**는 최소 70단어(정답 구간 95백분위수), 최대 374단어(검색 인코더 512토큰 ÷ 실측
  1.366 토큰/단어)로 분할·병합하는 규칙이다. 두 값 모두 점수 최적화로 고른 값이 아니다.
  10개 조건 전부에서 유의 개선했고, 최소 길이 미달 청크가 0%가 됐다.
- **주 발견: 정규화 이후 성능의 91%가 잔여 청크 크기로 설명된다.**
  `DCG@20 = 0.0221 × 평균단어 + 46.03`, 상관 +0.914 (p = 0.00022), 잔차 RMSE 0.148.
  임계 규칙 6종에 임의 조절값 3종이 섞였는데도 **평균 단어 수 하나로 ±0.15 안에서 맞는다.**
  그 결과 순위가 뒤집혀 **폐기한 규칙이 채택 규칙보다 높게 나온다.**
  ⇒ 이 과제에서 지배 요인은 **임계 규칙의 품질이 아니라 청크 크기**다.
  보고 주값은 사전 등록대로 적응 임계(50.53)로 유지한다.
- **범위 제약 디코딩의 의의:** 분위수 임계를 "분위수 + 길이 범위 제약"으로 바꾼 것이며 **온라인**이라,
  분절 트랙의 경계 개수 제어 문제에 직접 대응한다. **이식 후보**이나 범위 값을 분절 연습 데이터에서
  새로 유도하고 Score 기준으로 별도 사전 등록해야 한다.
- **범위 제한:** 길이 정규화는 검색 청킹 전용 어댑터다. 분절기 동결 설정과 체크포인트는 바뀌지 않았고,
  시험지는 열지 않았다. 정규화의 병합 단계는 최종 청크 크기를 알아야 해서 오프라인이며
  온라인 주장을 훼손하는데, 이 결함은 범위 제약 디코딩이 해소한다.

| LoCoMo 사건 단위 검색 → 질의응답 | **미실행** — M4~M7 완료 후. 검색기는 기존 SOTA를 적용하고, 검색 턴 수에 상한을 둬 정확도 대 컨텍스트 크기의 파레토로 본다. 착수 시 주인공 축의 다화자 재설계가 선행 조건 |
