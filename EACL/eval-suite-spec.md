## 1. 구성

|---|---|---|---|---|---|
| `listener-dev3` | Pieman(Michelmann 2021) · Tunnel(**Lositsky 2016**) · Monkey | 청취자 버튼프레스 시계열 → 합의 경계 | 3 | **dev** (D-M5-a 로 소진) | 무제한 |

**출처 표기 주의.** 셋을 "Michelmann 데이터"로 뭉뚱그리면 부정확하다. **Tunnel 의 사람 경계 원소스는

경계 수도 판본에 따라 다르다 — Pieman 96문장/18경계 · Tunnel 504/18 · **Monkey 408/30(goldA)·40(goldB)**.
Monkey 를 쓸 때는 어느 gold 판본인지 반드시 명시한다.

**규모의 한계 (프로젝트 내부 판단).** `tier2-heldout-spec.md` §0 은 "사람이 사건 경계를 주석한 **텍스트**
데이터는 사실상 3편뿐"이라고 적었다. 이는 우리 판단이며 Michelmann/Kumar 가 공개한 자극 전체를
전수 확인한 결과는 아니다. 자극을 늘리려면 원 논문·저장소를 직접 확인해야 한다.

## 2. `sceneml-test6` 을 넣기 전에 해결해야 하는 것

**⚠️ 아래 셋이 미해결이다. 해결 전에는 후보 지위로만 둔다.**

### ① 주석 대상이 다르다 (구성 타당도)

ScANT 는 SceneML 스킴으로 **SCENE** 을 주석하고, 이벤트나 SDS 자체는 별도 주석 없이
SCENE 의 속성값으로 확장 가능한 형태로 남겨 두었다. 즉 *장면 전환* 과 우리가 재는
*사건 경계* 가 같은 것이라는 보장이 없다. 둘을 한 평가셋으로 섞어 평균 Score 를 내면
서로 다른 구성개념을 합산하게 된다.

**처리:** 별도 표로 보고하고 `listener-*` 와 평균 내지 않는다. 논문에서는
"cross-scheme robustness" 성격의 보조 결과로 위치시킨다.

### ② 표본이 너무 작다 (통계적 한계)

독립 단위는 챕터가 아니라 **작품**이다. 같은 작품의 여러 챕터는 강하게 상관되므로
챕터를 독립 표본으로 세면 신뢰구간이 부당하게 좁아진다.

- 실질 최상위 독립 단위 = 최대 6작품 → t 계수 약 2.57.
- `listener-*` 는 3편 → t 계수 약 4.30.

**주장 가능:** 실행 가능성 · 효과 방향의 일관성 · 명백한 실패 사례 · 도메인 이동 민감성.
**주장 불가:** 일반적 성능 우위 · 작은 Score 차이의 유의성 · 장르 전반 일반화 ·
5축 중 어느 축이 우월성의 원인인지.

**처리:** 점추정치만 쓰지 말고 **작품별 점수 + 계층 bootstrap CI** 를 함께 보고한다.

### ③ 저자 격리가 미완이다

ScANT 6편 중 5편의 저자는 확인해 학습 코퍼스에서 격리했다(2026-08-03 재빌드).
**여섯 번째 "아동물 한 편"의 저자를 아직 특정하지 못했다.**

| 저자 | 작품 | 격리된 편수 |
|---|---|---|
| Doyle, Arthur Conan (1859-1930) | 셜록 홈즈의 모험 | 135 |
| Dickens, Charles (1812-1870) | 두 도시 이야기 | 81 |
| Fitzgerald, F. Scott (1896-1940) | 위대한 개츠비 | 19 |
| Baum, L. Frank (1856-1919) | 오즈의 마법사 | 12 |
| Austen, Jane (1775-1817) | 오만과 편견 | 0 (코퍼스에 원래 없음) |
| **미상** | **아동물 1편** | **미확인** |

재빌드 코퍼스 `pg_shorts_personkey_cap20_scant.jsonl` 검증 결과 위 5명 **전부 0편**이며,
성 단위 전수 검색에서 남은 `Fitzgerald, M. (Artist)` 2편 · `Austen, Sidney` 1편은 **동명이인**이다.
`Pohl, Frederik`(dev-3 Tunnel) 도 0편.

**처리:** 여섯 번째 텍스트의 저자를 ORDA 공개 자료에서 확인하고, Gutenberg 단편집에
작품이 있으면 격리 후 재빌드한다. 확인 전에는 `sceneml-test6` 을 개봉하지 않는다.

## 3. 개봉 순서 (봉인 규약)

1. `listener-dev3` 에서 방법 · 경계 자가결정 규칙 · 모든 하이퍼파라미터 · 보고 형식을 **동결**한다.
2. 동결을 commit/tag 로 고정하고 ledger 에 선언한다. **고치기 전에 선언해야 clean 하다.**
3. `listener-test3` 개봉 — 최초 1회, 재선택 금지.
4. `sceneml-test6` 은 §2 셋이 해결된 뒤 개봉. 보조 표로만 보고.

**금지:** 점수를 본 뒤 임계값·집계 규칙·부분집합을 바꾸는 것. 점수를 한 번이라도 본 데이터는
그 시점에 dev 로 확정되며 test 주장에 쓸 수 없다.

### `listener-*` 의 consensus 경계를 새로 만들 경우

버튼프레스는 이산 gold 가 아니라 시계열이므로 임계값을 걸어 합의 경계를 유도해야 한다.
**임계값을 우리 점수를 보고 고르면 즉시 규칙 위반이다.**

- 반응지연 보정 · smoothing · 임계값 · 최소 간격 · 텍스트 정렬 규칙을 **모두 사전 명시**한다.
- 임계값 선택이 필요하면 참가자 재표집 안정성 · split-half agreement 같은
  **인간 주석 내부 기준만** 쓴다. 모델 출력은 근거로 쓰지 않는다.
- 자극별로 튜닝하지 말고 **하나의 전역 규칙**을 쓴다.
- 규칙과 코드를 해시로 동결한 뒤에만 모델을 1회 실행한다.

현재 `listener-dev3` 는 이미 dev 로 소진되어 이 절차의 대상이 아니다. 자극을 **늘릴 때** 적용한다.

## 4. 지표

주지표는 공식 DTS **Score** 단일 숫자다 (`CLAUDE.md` 최상위 규칙).

```
Score = 0.5·F1 + 0.25·(1 − Pk) + 0.25·(1 − WindowDiff)
```

평가 모드는 **deployable** — 분절기가 경계 개수를 스스로 정한다. gold 개수를 방법에 주지 않는다.
matched@gold(=top-N)는 ranking 진단으로만, "oracle 개수 사용" caveat 를 붙여 보조로 쓴다.

mode · 부분집합 · t\* 가 다른 두 Score 를 직접 나란히 비교하지 않는다.

## 🔓 봉인 시험지 개봉 선언 (2026-08-04, 사용자 지시)

**연 것:** `listener-test3` = Run · GoHitler · MyMothersLife (*Born a Crime* 발췌, 사람 20명 주석).
메인 gold = **`goldtopn`** (`eventrecall_gold_gate.json`: author-filtered gold 는 경계밀도
0.47~0.53 으로 게이트(비율 상한 2.0) 미통과 → `passed: false`, main_gold=goldtopn).
topn 경계밀도 = run 0.0940 · gohitler 0.1161 · mymotherslife 0.0936.

**개봉 시점의 상태 — 동결되지 않았다.** Claude 가 순서(동결 후 개봉)를 권고했고 사용자가
재확인하여 개봉했다. 개봉 당시 미확정 사항을 그대로 기록한다:

- 오늘 앵커 코퍼스를 교체했다(10,598 → 11,836편, 인물키 상한 + ScANT 격리).
- 오늘 train/val 분할을 작가 단위로 바꿨다(기존 `none` 은 val 의 96.1% 가 train 에 같은 작가).
- 오늘 epoch 상한을 8 → 40 + val 손실 조기종료로 바꿨다.
- **val 손실과 dev-3 성능이 반대로 움직이는 것을 발견했으나 처리 미결정**
  (val 3.4818 → 3.3488 개선인데 dev-3 primary Score 0.4083 → 0.3857 하락).
- M4(= ablation 1, 5차원→1차원)가 아직 실행 중이었다.
- leave-one-out ablation 재실행 전이었다.

**⚠️ 이후 규칙.** 이 개봉 이후 위 항목을 고치면 `listener-test3` 는 dev 로 강등된다.
시험지는 유효 n≈1(3편이 같은 작품·저자)이라 대체재가 없다. ledger D-M11 ① 이 기록한 오염의
본질은 "가중치가 아니라 **결과를 보고 설계를 유지·변경한 연구자 선택**" 이며, 같은 기준이 적용된다.

**작동점.** 적응임계(문서 내 상위 rate 분위수), rate = 앵커 경계율 0.0657 동결.
test3 gold 밀도(0.094~0.116)를 쓰지 않는다 — 그것을 쓰면 oracle 누출이다.
따라서 BOR < 1(과소분절)이 구조적으로 예상된다. 이는 방법의 한계이지 측정 오류가 아니다.

**지표.** Score = (2F1 + (1−Pk) + (1−WD))/4 문서단위 평균 · BOR = 예측/정답 경계 수 ·
Lift = P(y=1|ŷ=1)/P(y=1) · 퇴화 하한(무예측 Score) 병기.

### 🔓 2차 개봉 — epoch 스케일링 비교 (2026-08-04, 사용자 지시)

**한 것:** 8 epoch 체크포인트(`_es_`)를 같은 시험지에 추가 채점해 40 epoch 과 비교.

| 설정 | val 손실 | dev-3 Score | **test3 Score** | test3 Lift |
|---|---|---|---|---|
| 8 epoch | 3.4818 | 0.4083 | 0.3981 ± 0.0117 | 1.842 |
| 40 epoch | **3.3488** | 0.3857 | **0.4269 ± 0.0086** | **2.428** |

퇴화 하한 0.3092 · BOR 둘 다 0.698(적응임계라 개수 동일, 위치만 다름).

**지위 강등.** 두 설정을 시험지 위에서 비교했으므로 **시험지는 epoch 결정에 관해 개발셋이다.**
"8 vs 40" 비교는 held-out 증거로 쓸 수 없고 개발 결과로만 보고한다.
단 40 epoch 단독 성능(0.4269)은 1차 개봉에서 동결 설정으로 1회 측정한 값이라 유효하다.

**정정.** 1차 개봉 직후 Claude 가 "앵커에 더 잘 맞을수록 사람 경계에서 멀어진다"고 해석했으나
**틀렸다.** dev-3 한 점만 보고 내린 결론이었고, 시험지는 반대 방향이다. val 손실·시험지 Score·
시험지 Lift 셋이 모두 "더 학습할수록 좋다"로 일치하며, dev-3 만 예외다. dev-3 은 3편이고
pieman 에 선택압이 9회 누적된 연습장(D-M5-a)이므로 그쪽이 잡음일 가능성이 높다.
