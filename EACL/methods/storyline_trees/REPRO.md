## 1. 범위 (사용자 결정, 2026-08-03)
논문의 주 기여는 스토리라인 트리 기반 **적응 검색과 서사 QA 정확도**
(DetectiveQA · NovelQA · LiteraryQA)다. 장면 분절(§3.1)은 트리의 기본 단위를 만드는 전처리다.
**§3.1 만 구현**하고 QA 수치는 대조하지 않는다. Top-down/bottom-up 트리 유도(§3.2·3.3)와
적응 검색(§4)은 범위 밖이다.

## 3. 구현한 것 (`segment.py`)
장면 = 시간·장소·서사 초점이 대체로 일관된 연속 구간, 그중 하나가 바뀌면 경계.
1. 원문을 **장(chapter)** 단위로 파싱.
2. 장마다 문장에 `[1] [2] …` 번호를 붙이고 **전 작품 공통의 표준 프롬프트**를 건다
   (책마다 프롬프트를 바꾸지 않는 것이 논문의 설계 의도 — 분절 일관성 확보).
3. 모델은 장면별 `scene_title` / `ending_sentence` / `synopsis` / `significance` 출력.
   경계 복원의 근거는 **`ending_sentence`**(장면의 마지막 문장 번호)이므로,
   다음 장면의 시작 = `ending_sentence + 1` 번째 문장.
4. 검증 — 오름차순, 마지막 장면의 `ending_sentence` == 장의 마지막 문장 번호.
   실패 시 재시도 후 폴백(장 통째 1장면).

## 4. 논문에 없어 우리가 정한 것 (반드시 병기)
- **장이 컨텍스트를 넘칠 때**: 논문은 "원문을 장으로 파싱한다"까지만 말한다. 넘치면 호출이
  실패하므로 단어 상한(기본 12,000) 그리디 분할을 폴백으로 뒀다.
- **장 표지 인식 규칙**: 정규식 기반(LitSeg 구현과 동일 계열).
