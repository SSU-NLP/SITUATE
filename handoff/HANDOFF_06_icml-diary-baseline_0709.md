# HANDOFF_06 — ICML 참관기 화제분절 비교 기준선 (새 방법론 개발 전 baseline)

**지정일**: 2026-07-09 · **상태**: 비교 기준선 확보(고정) · **용도**: 앞으로 만들 새 화제분절 방법론의 *before* 비교대상

## 0. 문제 정의

- **배경**: 새로운 화제분절 방법론을 개발할 예정. 그 전에, 동일 입력에 대한 기존 2방법의 분절 결과를 **문장 단위로 고정 기록**해 비교 기준선으로 남긴다.
- **비교 2방법**: (A) 우리 방법 = LLM 없는 Hi-OnTop δ_eff 임베딩 분절 / (B) LLM 방법 = two-stage spike-gated LLM judge(우리 신호로 후보 → 후보에서만 LLM NEW/SAME).
- **목표**: 이 ICML 2026 참관기(한국어 산문, 89문장)에 대해 두 방법이 *원문의 어느 문장을 경계로 삼았는지 전부* 기록(요약 금지).
- **성공기준**: 새 방법을 이 입력에 적용했을 때, 아래 §3/§4 경계와 문장 단위로 직접 대조 가능.

## 1. 데이터 (원문)

- **출처**: 사용자의 ICML 2026 참관기 블로그 글 (2026-07-09 제공). ICML 2026 = 서울 코엑스, 7/6(월)~7/11(토). 원문 전문 = §5.

- **전처리**: 문장 종결부호(`.?!`) 기준 분리 → **89문장**. **1문장 = 1 turn** (이 글은 대화가 아니라 산문 → *sentence-as-turn 근사*; 우리 방법론은 원래 대화/스트리밍 turn 대상).

- **⚠ 문장분리 부산물(경계 노이즈 원인, 그대로 보존)**: 원문의 `..ㄷㄷ)` 가 문장[20] `(심지어 7개 국어를 구사하신다고..` 와 문장[21] `ㄷㄷ) 현재는 …` 로 쪼개짐. 또한 문장[39]는 `'Position:` 의 콜론 때문에 turn 파서가 화자= `'Position` 으로 분리해 인코딩 텍스트에서 `'Position:` 이 빠짐(경계 인덱스는 불변). 두 부산물 모두 아래 기록에 그대로 남김.

## 2. 방법·설정 (재현)

**공통**

- 인코더: `sentence-transformers/paraphrase-multilingual-mpnet-base-v2` (768D, L2정규화, 다국어/한국어). backend=local.
- δ_eff 정식 config: `ctx_window m=2`, `ctx_decay ρ=0.7`, `ctx_blend a=0.5` (`run_encoder_comparison` M,RHO,A). δ_eff = a·δ_prev + (1−a)·δ_ctx, δ=1−cos.
- 스크립트: `scripts/segment_manual.py`, `scripts/segment_manual_llm.py`, `scripts/segment_manual_common.py`. seed 불요(인코더 forward + 규칙/LLM temp0 = 결정적).
- 입력파일: 문장분리본 `icml_sentences.txt` (89줄).

**방법 A — 우리 방법 (LLM 없음)**

- `HiOnTopV2` 적응임계 `μ + c·σ`, **c=1.0 고정(calibration-free)**, `warmup=5` (warmup 전 δ*=0.5594 fallback). ⚠ c는 튜닝 대상 아님(고정) — 잔여 c-민감도는 decision-log 2026-06-15 미해결 한계.

- 명령: `uv run python scripts/segment_manual.py --file icml_sentences.txt --c 1.0`

- 결과: **14 세그먼트 (경계 13)**.

**방법 B — LLM 방법 (two-stage spike-gated judge)**

- Stage1 후보생성(우리 신호, 0-lag): `gen_peak(δ_eff, k=0.5, W=20)` — s_t 가 직전 상승 AND 최근 W턴 robust baseline(med+k·1.4826·MAD) 초과 → 후보. **후보 20개**: [6, 7, 18, 20, 25, 27, 29, 31, 34, 51, 53, 54, 57, 59, 61, 69, 71, 74, 79, 87].

- Stage2 판정(후보에서만): system=`segmentation_prompts/judge_binary_neutral_v1.md`, model=`openrouter/openai/gpt-4o`, temperature=0, max_tokens=4, 과거맥락+현재발화 → `NEW`/`SAME`. 경계=NEW.

- 맥락 길이 2종 기록: **full-past(`--ctx-k 0`)** 와 **bounded `--ctx-k 6`**.

- 명령: `uv run python scripts/segment_manual_llm.py --file icml_sentences.txt [--ctx-k 6]`

- 결과: full-past → **5 세그먼트(경계 4)** / ctx-k 6 → **10 세그먼트(경계 9)**.

[24] 런던의 Mistral AI에서 Technical Project Manager를 맡고 계시는 분인데 영어 공부는 어떻게 하셨는지, 조직 생활 내에서 서로 피드백해야 할 때 감정 상하지 않게 하는 방법이 있는지 등을 물어봤던 것 같다.
[25] 그 중 감명 깊었던 조언이 3가지 있었다.
[26] 넓은 인맥과 면접 대비를 위해 질문하는 습관 기르기 (미리 모든걸 사전 조사하고 좋은 질문으로 좋은 인상 남기기) 시키지 않은 일이라도 조직에 필요해 보이면 만들어서 하는 능력 키우기 (시킨 일은 디폴트로) 조직 생활 시 긍정 마인드 갖기 (피드백 받을땐 감사하게 듣고, 줄땐 돌려서 말하기) 'Factored Latent Action World Models' 포스터 기존의 Latent Action Model(Genie, AdaWorld 등)은 행동 라벨이 없는 비디오로도 월드모델을 학습 가능하게 해주지만 전체 장면의 전환을 하나의 통합된 잠재 행동으로 압축해버린다.

[28] 따라서 FLAM은 공유 공간 내 모든 개체에 고유한 행동을 부여하여 문제를 해결했다.
[29] 월드모델이라는 주제의 최신성도 좋았고 Latent Action Model의 핵심을 배울 수 있어 흥미로웠지만, 한편으로는 현실적인 연산 비용 문제가 발생할 거라는 생각이 들었다.
[30] 만약에 버스에서 갑자기 10명이 내리면서 개체가 확 늘어난다면 연산 비용을 어떻게 감당하는지 질문했고, 이에 대해서는 앞으로 후속 연구가 더 진행되어야 할 과제라고 하셨다.
[31] 사실 인간조차도 시야 내에 있는 모든 개체의 행동을 동시에 인지하고 처리하지는 못한다.
[32] 대신 움직임의 변화가 크거나 중요도가 높다고 판단되는 일부 개체들에만 주의를 집중시킨다.
[33] 월드모델 역시 이처럼 중요한 신호만을 선별적으로 포착하여 처리한다면, 연산 비용을 획기적으로 줄이면서도 인간과 더욱 유사하고 효율적인 방식으로 작동할 수 있지 않을까 싶다.
[34] ICML에 와서 처음으로 네트워킹 해보니까 생각했던만큼 많이 떨리지 않고 재밌었다.
[35] 다만 영어 발음이 좀 또박또박하신 분들에게 확실히 시선이 갔던 것 같다.
[36] 만약 나도 해외 학회에서 발표하게 된다면 억양과 발성 연습은 꼭 해야겠다고 느꼈다..
[37] 두 번째 포스터 리뷰는 주제가 달라지는 관계로 다음 글에서 이어가겠다.
[38] 이어서 리뷰할 포스터는 내가 작년 KSC와 올해 EMNLP를 준비하면서 다뤘던 연구 주제랑 비슷해서 관심이 갔다.
[39] 'Position: Hippocampal Explicit Memory Is the Cornerstone for AGI' 포스터 나는 인간과 상호작용하는 AI임에도 여전히 인간이 잘하는 영역에는 부족함이 많다고 생각한다.
[40] 아무리 AI가 인간이 못하는 영역을 잘해도 인간의 잘하는 영역(시각적∙언어적 추론 능력)을 따라가지 못하면 인간은 AI에게 답답함을 느낄 것이다.
[41] 그렇기에 'AI는 인간을 닮도록 설계해야 한다'는 연구 철학을 가지고 있다.
[42] 예를 들어, 연속으로 사용자 입력이 들어오는 real-time streaming 환경에서 인간은 에피소드 단위로 기억하는 데 능숙하지만 AI는 기억 체계가 명확히 잡혀있지 않다.
[43] ChatGPT나 Claude 같은 turn-based 환경은 턴 단위로 기억을 관리하면 되지만, 일상 대화나 비디오 같은 real-time streaming 환경에서는 기억 단위가 애매하기 때문이다.
[44] 따라서 인간과 닮은 체계적인 기억 관리를 위한 real-time streaming 환경에서의 화제 분절 연구를 진행하고 있다.
[45] 해당 연구도 범용적인 인공지능(AGI)은 여러 지식을 신속하게 인코딩, 검색, 업데이트 및 조직화하기 위해 인간처럼 외현적인 기억 체계를 필요로 한다고 주장한 점에서 나의 연구 방향과 일치했다.
[46] 해당 연구는 인간 뇌에서 기억 관리하는 방식을 2가지로 정의한다.
[47] 다시 말해서 implicit memory는 뛰어난 학습기이지만 기억을 능동적으로 인출해내지 못하며, explicit memory는 유연한 지능과 추론을 가능하게 한다.
[48] 그러나, 현재 LLM의 메커니즘은 인간의 implicit memory과 유사하게 통계적 패턴 학습기로서 기능하기 때문에 다음과 같은 한계가 있다.
[49] 지식이 중첩된 파라미터 내에 dense하게 인코딩됨으로 개별적인 기억 요소를 분리하고 저장하는 구조적 능력 부족, 예측 오차를 반복적으로 최소화하는 방식으로 학습하여 새로운 관계를 바로 지식으로 결합하는 원샷 바인딩이 불가능, 훈련이 끝나면 기억 상태가 frozen되어 실시간 지식 습득이나 불필요한 지식의 선택적 망각이 불가능.
[50] 인간의 explicit memory를 LLM에 적용해야 하는 필요성은 다음과 같다.
[51] 재학습 없이 단 한 번의 경험으로부터 새로운 지식을 습득할 수 있다.
[52] 모델이 스스로 무엇을 알고 있는지, 그 지식의 출처는 어디인지 인지할 수 있다.
[53] 훈련 시 본 적 없던 새로운 입력에 대해서도 추상적인 규칙을 적용할 수 있다.
[54] 문맥 유지 한계를 넘어서서 일관된 목표와 상태를 유지할 수 있다.
[55] 행동을 취하기 전, 과거의 일화 기억들을 재조합하여 결과를 미리 시뮬레이션할 수 있다.
[56] 이를 통해 동적 학습, 계획 수립, 메타인지, 기호 추론, 그리고 정신적 시뮬레이션을 수행할 수 있다.
[57] LLM이 explicit memory를 제공하기 위해 필요한 요소는 다음과 같다.
[58] Sparse 인덱싱, Loss-free 업데이트, 연상 구조, 패턴 분리, 패턴 완성, 동적 기억, 원샷 학습, 적응형 망각.
[59] 그동안 내가 구상해 오던 연구랑 비슷했지만, 내가 가진 뇌과학적 지식보다 훨씬 학술적 깊이가 느껴져서 향후 내 연구에 큰 도움이 될 것으로 기대된다.
[60] 다만 포지션 페이퍼인만큼, 메모리를 어디서 어떤 단위로 관리할지, 그리고 비용 문제는 어떻게 해결할지에 대해서는 아직 다루지 않았다는 답변을 받았다.
[61] 발표자께서는 지도교수님의 업스테이지 동료이셨던 미국 텍사스대 컴퓨터과학과 박사 과정의 박상준 연구원이셨다.
[62] 앞으로 기회가 된다면 꼭 공동 연구를 해보고 싶다고 말씀 드리고 서로 LinkedIn 팔로우도 했다.
[63] 결론적으로 'explicit memory' 관련 포스터와 이전 글에서 언급한 '월드모델' 관련 강연 및 포스터는 LLM이 가지고 있는 할루시네이션 등의 추론 능력 문제를 보완하고자 인간과 더 가까운 범용적인 인공지능(AGI)를 만든다는 공통점을 가진다.
[64] 월드모델 관련 강연 및 포스터는 LLM이 다음 텍스트 토큰을 예측하면서 학습한다면, 월드모델은 IDM을 통해 다음 행동을 예측하고 그에 따라 다음 상태가 어떻게 변할지 예측하면서 학습한다.
[65] 이는 자연스러운 맥락만 고려하는걸 넘어서 인간처럼 미래를 고려할 수 있게 한다.
[66] explicit memory 관련 포스터는 LLM이 일반화된 경험을 학습하는 implicit memory 역할을 하므로, explicit memory를 도입한다면 확률적으로 희석되지 않는 경험을 학습할 수 있다.
[67] 이는 인간처럼 기억을 능동적으로 인출해냄으로써 유연한 지능과 추론을 가능하게 한다.
[68] 따라서 지금은 LLM의 메모리 연구를 하고 있지만, 언젠가 비전-언어 월드모델(VLWM) 연구도 해보고 싶다.
[69] 오늘은 오전에만 학회에 방문하여 어제 LinkedIn 팔로우를 맺었던 박상준 님, 그리고 파파고 리서치 엔지니어 김현우 님과 점심 식사를 함께하면서 대화 나누는 자리를 가졌다.
[70] 바로 옆 자리에 앉게 되어 이번 연구와 앞으로의 연구에 대해 많은 질문을 할 수 있었다.
[71] 포지션 페이퍼는 실험이 없는 대신 근거를 체계적으로 제시하는게 가장 중요하다.
[72] 비슷한 맥락으로 새로운 task를 제시하는 연구라면 단순 성능뿐만 아니라 그 필요성을 실험이나 논문 근거로 보여주는게 매우 중요하다.
[73] 실제로 이번 연구도 explicit memory의 대안이 이미 있지 않냐는 rebuttal을 받았다고 한다.
[74] 이에 어떻게 답변했는지 궁금했다.
[75] 나도 화제 분절 연구를 하는 목적이 explicit memory 구현 때문이므로, 내 연구의 필요성을 설득하고 방향성을 잡으려면 OpenReview의 질의응답을 한 번 읽고 가야겠다고 느꼈다.
[76] 한편, 내가 새롭게 제시할 '실시간 화제 분절 task'의 데이터는 turn-based 환경이 아닌 실시간 스트리밍 환경이어야 한다는 조언을 받았다.
[77] 이미 ChatGPT나 Claude 같은 turn-based 환경에서는 턴 단위로 메모리를 관리할 수 있으므로, 굳이 에피소드 단위의 메모리로 재구성할 필요성이 떨어지기 때문이다.
[78] 반면 음성이나 비디오 같은 실시간 스트리밍 환경에서 explicit memory를 구현하려면 에피소드 단위의 메모리 관리가 필수적이며, 이를 위해 실시간 화제 분절 task가 반드시 선행되어야 한다는 논리를 공고히 할 수 있었다.

[80] 이걸 쓰고 가야 앞으로의 모든 연구에 방향성이 잡히기 때문이라고 하셨다.
[81] 포지션 페이퍼의 구체적인 용도를 잘 몰랐는데, 이번 기회를 통해 어쩌면 스케일이 큰 연구의 개요를 잡는 데 반드시 필요한 용도임을 깨달았다.
[82] 다음 연구로는 explicit memory를 실험 및 분석할 예정이라고 하셨다.
[83] 내가 화제 분절 연구를 진행하는 궁극적인 이유는 explicit memory의 기억 단위를 정의하기 위해서였다.

## 6. 관찰 (새 방법론 설계 참고 — 판단은 codex 위임 대상)

- **A(우리, 14세그)**: 임계만으로 판정 → 실제 화제전환(강연·인물소개·네트워킹·포스터·둘째날점심·포지션페이퍼)은 대체로 잡으나, 문장분리 부산물([20],[21])·강연 세부([7],[27]) 에서 **노이즈 경계**. c=1.0 고정값이 그대로의 답(튜닝 금지).

- **B full-past(5세그)**: 노이즈 0이나 맥락이 길어질수록 LLM이 보수적 → 앞부분 과소분절(긴 맥락 후반부 붕괴, HANDOFF_02 §1B와 동일 현상).

## 7. 제3 방법 — EM-LLM (LLM 예측오차 surprise + 그래프 리파인먼트)

**추가일**: 2026-07-09 · **용도**: A(임베딩 거리)·B(LLM judge)와 성격이 다른 **제3의 경계 신호(LLM 토큰 예측오차)** 대조군. 새 방법론 설계 시 "LLM surprise를 쓰면 어디가 갈리나"의 참조점.

### 7.1 방법·설정 (재현)

- **출처**: EM-LLM (Fountas et al. 2025, github.com/em-llm/EM-LLM-model). 원본 2단계 그대로 이식:
  1. **Surprise = 생성형 LLM 토큰 NLL** `−log P(x_t|x_<t)` (단일 forward pass 부산물, **추가 LLM 호출 0회**). 문장 surprise = 그 문장 토큰들의 mean NLL.
  2. **경계(surprise)**: `s_i > mean(past) + γ·std(past)`, **γ=1.1**(원본 `surprisal_threshold_gamma` 기본) — `context_manager.py:923`.
  3. **그래프 리파인먼트**: 각 경계를 '원래 세그먼트 크기 2배' 국소 윈도우 안에서 이동시켜 `[0:t]/[t:T]` 이분할의 **modularity 최대(argmax)** 또는 **conductance 최소(argmin)** 지점으로 스냅 — `similarity_refinement/segmentation.py`. 유사도 `A[i,j]=Σ_{layer≥0,head}⟨repr_k_i, repr_k_j⟩` (블록 대표 key=문장 토큰 post-RoPE key 평균) — `em_llm.py:245,776`.
- **LM**: `Qwen/Qwen2.5-7B` (base, 비-instruct, 다국어/한국어, 로컬 A100 bf16). **API 과금 $0**. `refine_from_layer=0`(전체 28레이어 key 합산), `min_block_size=1`.
- **스크립트**: `scripts/segment_manual_emllm.py` (원본 `similarity.py` modularity/conductance 수식 verbatim 인라인). 결정적(temp 무관, forward만).
- **명령**:
  - `uv run python scripts/segment_manual_emllm.py --file icml_sentences.txt --gamma 1.1 --metric modularity`
  - `uv run python scripts/segment_manual_emllm.py --file icml_sentences.txt --gamma 1.1 --metric conductance`
  - 덤프: `outputs/emllm_modularity.json`, `outputs/emllm_conductance.json`.
- **⚠ 원본과의 (문서화된) 차이** — 비교 프레임 불가피:
  - 토큰 단위 아닌 **문장 단위** surprise 집계/경계 (A/B와 문장 대조용).
  - `repr_topk`: 원본은 attention repr_score 상위 1토큰; 여기선 attention 내부 점수를 밖에서 못 뽑아 **문장 전체 토큰 평균**으로 대표 key (repr_topk→all 근사).
  - surprise 임계 윈도우: 원본은 local memory(n_local) 구간; 여기선 online **full-past prefix** (`--win`으로 trailing 지정 가능), `warmup=3`.
  - **입력 파싱 차이**: EM-LLM은 파일을 줄=문장으로 직접 인코딩(turn 파서 미사용) → §2 부산물이던 `'Position:` 콜론 화자분리 없음. [39]는 `'Position: Hippocampal…'` 전문 그대로 인코딩됨.

### 7.5 관찰 (새 방법론 설계 참고 — 판단은 codex 위임)

- **① EM-LLM surprise는 "담화표지/구어 참신성"에 반응** — A(임베딩 거리)와 노이즈 원인이 다름. surprise 최고점이 [10]"아이언맨 실존"(3.55)·[20]"(심지어 7개국어"(3.32) 등 **구어체 감탄/삽입구**. A의 노이즈는 문장분리 부산물([20],[21])·기술 세부([27]). → 두 신호는 **직교(orthogonal)에 가까움**: 결합(late-fusion) 시 상보 가능성.
- **② surprise가 A·B 전부 놓친 [23](최유정 점심)을 단독 포착.** LLM은 "점심은…" 화자·장면 전환에서 예측오차 스파이크. 반면 A는 21→27 건너뜀.
- **③ ⭐ modularity 리파인먼트가 [39]('Position: Hippocampal…' 포스터 시작)를 단독 복구** — §6이 "Stage1 후보 없음 → B가 구조적으로 못 잡음"이라 명시한 사각지대. 리파인먼트는 surprise 스파이크가 아니라 **key 유사도 그래프의 최적 이분할**을 찾으므로 스파이크 없는 의미 경계도 국소 윈도우에서 발견. [18]·[16]도 recall.
- **④ 그러나 강한 합의 경계 [34]·[61]·[69](네트워킹·인물·점심)를 EM-LLM 3변형 모두 놓침.** A·Bfull·Bk6 전부 잡은 지점. → **LLM 예측오차 ≠ 인간이 느끼는 화제전환**의 대표 반례(특히 [34]는 nll=2.598로 평범). 새 task의 gold 정의 시 "예측오차형 경계"와 "장면/화자 전환형 경계"를 구분할 필요.
- **⑤ modularity > conductance (이 입력).** conductance 리파인은 [4,5,8]처럼 앞쪽 소구간에 몰려 알려진 topic 구조와 정합성 낮음(cut/vol 최소화가 작은 tight 커뮤니티 선호). modularity가 topic 경계와 더 잘 맞음.
- **⑥ ⚠ 리파인먼트 전제 위반**: surprise 경계 7개로 희소 → 세그먼트 장대화([25..53]) → '2× 윈도우'가 거대해져 리파인먼트가 **미세조정이 아닌 대폭 이동**(sur 54→mod 39, sur 65→mod 50). EM-LLM 리파인먼트는 **초기 경계가 촘촘할 때** 의도대로 작동. 산문+γ=1.1 조합의 희소 surprise가 이 전제를 깸 → γ 낮춰 초기 경계 밀도를 올리거나, 리파인 윈도우를 캡할 여지.
- **⑦ 비용**: B(턴당 GPT-4o API 최대 20콜)와 달리 EM-LLM은 **로컬 단일 forward 1회, 추가 LLM 호출 0**. 추론 LLM이 이미 돌면 경계 탐지 한계비용≈0. 단 A(인코더 only) 대비 풀 LLM 인프라 부담.
