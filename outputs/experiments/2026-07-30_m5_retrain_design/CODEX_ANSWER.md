## 결론

M5 재학습의 기본 설계는 다음으로 확정하는 것이 가장 타당합니다.

```text
학습 손실:
L = (1/5) Σk BCEWithLogits(logit_k, y_k)

ALPHA[k] = 1
pos_weight[k] = 1
축별 oversampling 없음
배포 시 확률 보정 없음
```

그리고 인과성은 모델의 5축 출력에는 유지하되, 사건경계 신호에서는 제외하는 것을 주안으로 권고합니다.

```text
모델 출력: 5축 유지
경계 신호: s_boundary = P(protagonist) + P(space) + P(time) + P(intentionality)
causality: 보조 출력·분석 대상으로만 유지
```

재학습과 개수 제어는 별도 트랙입니다. 순서는 “재학습으로 신호 의미를 먼저 고정 → 그 체크포인트에 대해 개수 제어 규칙 선택”이어야 합니다.

## 1. ALPHA와 pos_weight

### 확정안

- `pos_weight`: 전축 `1`
- `ALPHA`: 전축 `1`
- 현재 하드코딩된 `(1.0, 0.5, 1.0, 0.4, 0.25)` 제거
- `[1,30]` clip 자체도 제거
- 손실은 축 평균으로 계산

```python
loss = sum(
    F.binary_cross_entropy_with_logits(logits[:, k], labels[:, k])
    for k in range(5)
) / 5
```

### 근거

`pos_weight`와 `ALPHA`는 같은 종류의 가중치가 아닙니다.

- `pos_weight`는 한 축 내부에서 양성과 음성의 상대비를 바꿉니다. 따라서 최적 출력이 참 사후확률이 아니라 가중 사후확률이 됩니다.
- `ALPHA`는 해당 축의 양성·음성 손실을 모두 곱해 공유 표현에 대한 축별 경사량을 바꿉니다.

따라서 표의 `ALPHA × pos_weight`는 양성항의 상대적 경사 크기를 보여주지만, 손실 전체를 하나의 단순 가중치로 합친 것은 아닙니다. 그럼에도 현재 설계가 “클래스 균형”과 “축 중요도”를 근거 없이 동시에 섞고 있다는 결론은 맞습니다.

`ALPHA`는 독립된 무한용량 head라면 각 축의 이론적 최적확률을 바꾸지 않지만, 실제 M5는 인코더 이후 표현과 최적화 자원을 공유하므로 학습 결과를 바꿉니다. 근거 없는 ALPHA를 유지할 수 없습니다.

### clip을 풀어야 하는가?

`pos_weight`를 쓰지 않는 것이 주안이므로 clip 문제도 사라집니다.

진단 조건에서만 exact prevalence weight를 시험한다면 clip하지 말아야 합니다.

```text
time        pw = 45.512
causality   pw = 0.418
```

다만 이것은 운영 후보가 아니라 “불균형 최적화가 정말 필요한가”를 확인하는 진단 조건이어야 합니다. `pw<1`까지 허용하면 causality 양성을 의도적으로 약화하며, 출력은 더 이상 직접적인 사후확률이 아닙니다.

### 둘을 하나로 합칠 것인가?

아닙니다. 합치는 것이 아니라 목적을 분리해야 합니다.

- 확률 추정: proper scoring rule인 plain BCE
- 축별 표현학습 비중: 우선 전축 동일
- 경계에 대한 축별 유용성: 학습 손실이 아니라 별도의 경계 집계 규칙에서 처리
- 사후 calibration: 독립적인 사람 축라벨 calibration set이 생겼을 때만 검토

현재 silver prevalence를 이용한 역변환은 “가중 BCE가 만든 왜곡을 되돌리는 것”이지 사람 기준 calibration은 아닙니다.

## 2. pos_weight를 애초에 쓸 것인가?

주안에서는 쓰지 않는 것이 맞습니다.

plain BCE에서는 모델이 충분히 학습됐다는 조건 아래

\[
P_k = P(\text{reset}_k=1\mid x)
\]

이고,

\[
s=\sum_k P_k
\]

는 조건부 기대 리셋 축수라는 명확한 의미를 가집니다. M5의 합산 신호를 정당화하려면 이것이 가장 일관된 설계입니다.

time 양성이 약 6만 건이라면 “양성이 거의 없어 학습 자체가 불가능하다”는 상황도 아닙니다. 클래스 불균형만으로 `pos_weight=45.5`를 정당화할 수 없습니다. 중요한 것은 표본 수가 아니라 plain BCE에서 time의 판별과 최적화가 실제로 실패하는지입니다.

권고 순서는 다음입니다.

1. 자연 발생 빈도를 유지한 plain BCE로 학습
2. 축별 AUROC뿐 아니라 AUPRC, log loss, Brier, prevalence 대비 예측 평균을 진단
3. time의 순위 성능까지 붕괴할 때만 불균형 최적화 조건을 진단적으로 비교
4. weighted BCE가 필요하다고 판정되더라도, 배포 확률에는 analytic inverse correction을 적용
5. 사람 축라벨이 없으므로 이를 “human calibration”이라고 부르지 않음

앵커 holdout의 축별 수치는 학습 파이프라인 sanity check에는 사용할 수 있지만 모델 설계 선택이나 성공 판정의 게이트로 쓰면 안 됩니다.

## 3. causality 처리

### 권고: 5축 head에는 유지하고 경계 합산에서는 제외

세 선택지 중에서는 “그대로 포함”도, “ALPHA로 몰래 누르기”도 권하지 않습니다.

- 그대로 합산: 발화율이 약 0.68–0.71로 포화됐고 약축으로 반복 확인됐습니다. 보정된 합의 절반을 차지하는 것은 증거량이 아니라 높은 base rate의 결과입니다.
- ALPHA로 누르기: 학습 경사와 출력 품질을 바꾸면서도, 경계 집계에서 왜 causality가 약해야 하는지를 불투명하게 숨깁니다.
- 축 자체 삭제: 5축 표현 모델이라는 주장과 과거 결과의 호환성을 불필요하게 훼손합니다.

따라서 역할을 명시적으로 나눕니다.

```text
representation claim: 5개 축을 모두 예측
boundary bridge: 검증된 informative axes의 합
causality: auxiliary/diagnostic axis
```

이는 “5축 모두가 동등하게 사건경계를 결정한다”는 주장을 포기하는 결정입니다. 대신 “5축 factored representation을 학습하지만, 사건경계 검출에는 경험적으로 유효한 축만 사용한다”고 논문 문구를 좁혀야 합니다.

사전등록 비교는 최소한 다음 두 개면 충분합니다.

- `S5`: 다섯 확률의 합
- `S4`: causality를 제외한 네 확률의 합

연속적인 causality 계수 `λ∈[0,1]` 탐색은 다시 임의 ALPHA 문제를 경계 집계 단계로 옮길 위험이 큽니다. 우선 `λ=1` 대 `λ=0`의 가설검정으로 제한하는 편이 낫습니다.

## 4. 재학습이 2.4배 과분절을 해결하는가?

직접 해결한다고 기대하면 안 됩니다.

`μ+cσ`는 양의 아핀변환에 불변이므로 평균과 분산만 달라지는 calibration 개선은 경계 개수를 바꾸지 않습니다. 재학습이 순위, 꼬리 모양, 시간적 군집성 같은 비아핀적 구조를 바꾸면 개수가 일부 변할 수는 있지만, 그것은 보장되지 않는 부수효과입니다.

따라서 두 트랙으로 분리해야 합니다.

### 트랙 A — 측정 모델

- plain BCE 재학습
- 확률의 의미와 축별 출력 복구
- causality 포함 여부 결정
- 체크포인트 고정

### 트랙 B — 작동점과 개수 제어

- 고정된 신호에서 deployable 경계 선택 규칙 결정
- 누적 `μ+cσ`, causal EWMA, 최소간격 제약 등을 비교
- 서사와 대화의 작동점은 각 허용 선택셋에서 선택

순서는 반드시 A 다음 B입니다. B를 먼저 맞춘 뒤 모델을 재학습하면 신호 분포와 경계 군집성이 바뀌어 작동점을 다시 선택해야 합니다.

또한 “최소간격 NMS”가 미래 문장을 비교하는 대칭 NMS라면 deployable의 미래 미사용 조건과 충돌합니다. 주안은 스트리밍 방식의 refractory rule이어야 합니다.

```text
임계 초과 경계를 채택한 뒤, 다음 g개 전이는 경계 후보로 채택하지 않음
```

혹은 suppression 구간 안에서 최초 초과점만 채택합니다. 미래 최대값을 기다리는 방식은 별도 비배포 분석으로만 둘 수 있습니다.

## 5. 권고 사전등록 설계

### 단계 0 — 구현 잠금 및 재현성

공통 조건을 먼저 고정합니다.

- 동일 데이터 split
- 동일 frozen mpnet 특징
- 동일 seed 집합, 권고 3개 이상
- 동일 optimizer, epoch, batch 구성
- 자연 빈도 minibatch sampling
- 동일 checkpoint-selection 규칙
- 앵커 holdout은 학습 이상 진단만 수행
- dev-3 및 대화 선택셋은 학습 중 보지 않음

현재 체크포인트를 보존하고 새 모델 ID를 사용해야 합니다. 바로 `m5_default`를 덮어쓰지 말고 게이트 통과 후 승격하는 것이 안전합니다.

### 단계 1 — 손실 설계 게이트

조건은 세 개면 충분합니다.

| 조건 | ALPHA | pos_weight | 목적 |
|---|---:|---:|---|
| W0 | 기존값 | clipped 기존값 | 재현 기준 |
| W1 | 전축 1 | 전축 1 | 주안 |
| W2 | 전축 1 | exact odds, clip 없음 | 불균형 최적화 진단 |

W2 배포 출력에는 analytic inverse correction을 적용합니다. raw weighted probability와 corrected probability를 둘 다 기록하되, raw 합을 운영 후보로 사용하지 않습니다.

#### 손실 게이트

W1을 기본 채택합니다. 다음이 동시에 관찰될 때만 W2를 재검토합니다.

- plain BCE에서 희소축의 판별 성능이 seed 전반에 걸쳐 실질적으로 붕괴
- W2가 그 판별 성능을 일관되게 복구
- inverse correction 후에도 서사와 대화 선택셋의 주지표 방향이 W1보다 일관되게 우세

단순히 앵커 AUPRC나 time recall이 좋아졌다는 이유만으로 W2를 채택하지 않습니다. 앵커는 선택 기준이 아니기 때문입니다.

W0는 새 기본 모델 후보가 아닙니다. 재현과 변경 영향 산출용입니다.

### 단계 2 — 축 집계 게이트

W1 체크포인트를 고정하고 다음만 비교합니다.

- `S5 = Pp + Ps + Pt + Pc + Pi`
- `S4 = Pp + Ps + Pt + Pi`

각 신호마다 동일한 deployable 작동점 선택 절차를 적용해야 합니다. 같은 `c=1`만 비교하면 각 신호의 최적 작동점 차이를 축 유용성과 혼동할 수 있습니다.

채택 기준:

- dev-3에서 S4의 DTS Score Δ 방향이 3/3 seed 일치
- 대화 validation 60에서도 악화 방향이 일관되지 않거나 사전등록한 허용 열등폭 이내
- 경계 개수 오차가 개선되거나 최소한 악화하지 않음
- DTS test와 Born a Crime은 이 결정에 사용하지 않음

허용 열등폭은 결과를 보기 전에 정해야 합니다. 현재 정보만으로 과학적으로 정당한 숫자를 제가 확정할 수는 없습니다. 과거 seed 변동폭 또는 bootstrap CI로 정하는 추가 진단이 필요합니다.

dev-3에서 선택했다는 사실은 반드시 공시하고, 해당 셋의 절대 Score는 보고하지 않으며 Δ와 방향만 보고합니다.

### 단계 3 — 개수 제어 탐색

승리한 `W × S` 조합을 고정한 뒤 다음을 비교합니다.

- C0: 누적 `μ+cσ`
- C1: causal EWMA `μ_t+cσ_t`
- C2: C0 + causal 최소간격 `g`
- C3: C1 + causal 최소간격 `g`

탐색 파라미터는 작은 고정 grid로 제한합니다. 예:

```text
c ∈ {0.5, 0.75, 1.0, 1.25, 1.5, 2.0}
g ∈ {0, 2, 4, 8, 12}
EWMA span ∈ {20, 50}
```

span 5는 기존 결과상 다시 넣을 근거가 약합니다.

- 서사: dev-3에서 선택
- 대화: superseg validation 앞 60대화에서 선택
- DTS 공식 test: 최종 판독만
- Born a Crime 3편: 모든 결정과 코드를 고정한 뒤 1회 개봉

서사와 대화에서 서로 다른 `c/g`를 허용한다면 “도메인별 사전등록 작동점”이라고 명시해야 합니다. 하나의 범용 작동점을 주장하려면 두 선택셋을 함께 만족하는 단일 규칙을 미리 정의해야 합니다.

### 실패 판정

다음처럼 층별로 판정해야 합니다.

- 학습 실패: NaN, seed 발산, 축 출력 상수화, 희소축이 prevalence predictor 수준으로 붕괴
- 확률 설계 실패: W1이 W0보다 calibration은 개선하지만 두 선택셋에서 경계 Δ가 일관되게 악화
- causality 제외 실패: S4가 dev-3 또는 대화 선택셋에서 seed 일관 악화
- 개수 제어 실패: deployable 조건에서 과분절 감소가 DTS Score의 일관된 하락과만 함께 발생
- 일반화 실패: 선택을 고정한 뒤 DTS test 또는 봉인셋에서 방향이 뒤집힘

봉인셋 실패 후 같은 봉인셋으로 파라미터를 다시 맞추면 더 이상 봉인 시험이 아닙니다. 그 경우 결과를 실패로 기록하고 다음 버전용 개발자료로 전환해야 합니다.

## 최종 의사결정 요약

1. `ALPHA=1`, `pos_weight=1` 전축으로 재학습한다.
2. 현재 ALPHA와 clip된 pos_weight는 폐기한다.
3. weighted BCE exact-odds 조건은 진단군으로만 둔다.
4. causality head는 유지하되 경계 합에서는 제외하는 `S4`를 주가설로 검정한다.
5. 재학습은 확률·표현 트랙, 과분절 해결은 작동점·개수 제어 트랙으로 분리한다.
6. 새 체크포인트를 먼저 고정한 후 causal 최소간격/EWMA를 선택한다.
7. dev-3에서 골랐다는 사실을 공시하고 절대 Score는 인용하지 않는다.
8. 앵커 holdout은 모델 선택 게이트로 사용하지 않는다.
