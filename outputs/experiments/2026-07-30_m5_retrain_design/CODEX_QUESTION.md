# 의사결정 요청 — M5 재학습 시 축별 가중치(pos_weight × ALPHA) 설계 확정

한국어로 답해줘. 프로젝트 = /root/Hi-OnTop (EACL). 아래는 확정된 사실만 적었다.

## 배경 — M5 (FactoredSlot)
- 신호 `s_t = Σ_k P(reset_k)`, 5축 = protagonist_present / space / time / causality / intentionality.
- frozen 인코더(mpnet 768D) 위 1.43M 파라미터. 앵커 코퍼스 10,069편(2.79M 문장) 학습, k=1 silver 라벨(S_self 0.659 = 성능 상한).
- 배포 임계 = 누적 적응임계 `s_t ≥ running_mean + 1.0·running_std` (D-B39). dev-3 Score 0.3617, 예측 160 vs gold 66 = **2.4배 과분절**. 경계 개수 제어 = D-B34 이래 최대 미결.
- 앵커에는 **경계 gold 가 없다**(축별 리셋 라벨만). 축리셋→사건경계 다리는 `count ≥ t*` 하나뿐이었고 t*=3 은 폐기됨(D-B33 부칙1).

## 발견한 결함 (이번에 확인)
손실이 축마다 **두 겹**으로 가중돼 있다: `loss += ALPHA[k] * BCE_with_logits(logit, y, pos_weight=pw[k])`

- `ALPHA = (1.0, 0.5, 1.0, 0.4, 0.25)` — 하드코딩 상수 (factored_slot.py:24). 근거 기록 없음.
- `pw = np.clip((1-pos)/pos, 1, 30)` — 앵커 발화율에서 자동 계산 (train_anchor_m4m5.py:413).

| 축 | 실제 리셋율 | (1-p)/p | clip 후 pw | ALPHA | 곱 |
|---|---|---|---|---|---|
| protagonist | 0.3137 | 2.188 | 2.19 | 1.0 | 2.19 |
| space | 0.0952 | 9.504 | 9.50 | 0.5 | 4.75 |
| time | 0.0215 | 45.512 | **30.00 (상한 clip)** | 1.0 | 30.0 |
| causality | 0.7052 | 0.418 | **1.00 (하한 clip)** | 0.4 | 0.40 |
| intentionality | 0.1108 | 8.025 | 8.03 | 0.25 | 2.01 |

**결과: 확률이 심하게 miscalibrated.** 앵커 val 120편/32,907 전이 실측 (예측 meanP vs 실제 리셋율):
protagonist 0.532/0.314(1.70x) · space 0.308/0.095(3.24x) · time 0.248/0.0215(**11.56x**) ·
causality 0.551/0.705(**0.78x = 과소예측**) · intentionality 0.529/0.111(4.77x).
합 s = 2.169 vs 실제 1.246 = **1.74배 부풀림**.

pos_weight 사전보정 `p = q/(q+(1-q)·w)` 를 적용하면 합이 1.229 (실제 1.246, 오차 1.4%) 로 거의 정확히 복원된다.
단 **causality 는 pw=1 이라 보정이 항등식**이라 혼자 안 눌리고, 보정 후 s 안 비중이 25.4% → **51.4%** 로 폭증한다
(time 은 11.4% → 1.0% 로 소멸). causality 는 **약축으로 확정·트랙 종결**된 축이다(D-B13 조작화 5건 기각, D-B23 8회 실패, 발화율 0.68 포화).

## 이미 검정되어 죽은 것 (다시 제안하지 말 것)
- sticky-CRP κ + 우도비 스위칭 (설계 §4.4/§4.5) → **구현·검정 후 기각** (D-B28). 실패양상 = 사전이 우도에 눌림, 약 3배 과분절.
- `diag(β)` (SEM 식2) 도입 → codex 판정으로 기각 (L_pred 가 표현학습 보조손실이라 β 가 loss reweighting 으로 퇴화).
- 용량·학습HP(lr/epoch/slot_dim/bottleneck/dropout)·잔차특징·ψₑ → **전부 무효** (D-B30).
- 입력경로 분리만이 M5−M4 이득의 전부 (D-B34). M5 vs M6(dynamics 공유)는 3 seed 에서 구별 안 됨.
- 임계 규칙 국소성(EWMA span 5/20/50) → **개수를 맞추면 누적과 구별 안 됨**(D-B43 정정1). 단 gold 개수에 맞추면 EWMA span20/50 이 dev-3 에서 +0.050/+0.067 (3/3 seed) 로 이김.
- 🔑 **적응임계 μ+cσ 는 양의 아핀변환에 완전 불변**(실증 확인). ⇒ 신호를 아무리 잘 보정해도 그 규칙 아래서는 개수가 안 잡힌다(실측: s 평균 −43% 인데 개수는 −9%, 160→145).

## 데이터/오염 규약 (반드시 지킬 것)
- 서사 작동점 선택셋 = **dev-3 (pieman/tunnel/monkey, 사람 gold, 1005 전이/gold 66)** — D-B41 §2 가 허용, 단 "보고하는 셋에서 골랐다" 공시 필수. 절대 Score 인용 금지, Δ·방향만.
- 대화 선택셋 = superseg/validation 앞 60대화. DTS 공식 test 는 판독 전용.
- **앵커는 학습 자원**이지 검증/선택 기준이 아니다(사용자가 반복 지적).
- 봉인 시험지(신규 3편 Born a Crime) 미개봉.
- 주지표 = DTS Score = 0.5·F1 + 0.25·(1−Pk) + 0.25·(1−WD), 모드 = deployable(gold 개수 미사용·미래 미사용). AUC 는 보조.

## 물어보는 것 (각각 근거와 함께, 한국어로)
1. **ALPHA 와 pos_weight 를 어떻게 확정할 것인가?** 이중 가중치를 유지할 근거가 있나, 아니면 하나로 합쳐야 하나?
   특히 (a) pos_weight clip [1,30] 을 풀 것인가(time 45.5 / causality 0.418), (b) ALPHA 하드코딩 상수를 유지·제거·재도출 중 무엇인가.
   "확률 보정(calibration)"과 "축별 학습 비중"은 서로 다른 목적인데 지금 한 곱에 섞여 있다 — 이걸 분리하는 게 맞나?
2. **애초에 pos_weight 를 쓰는 게 맞나?** plain BCE(w=1 전축)면 출력이 곧 참 사후확률이라 `s = E[리셋 축수]` 가 절대적 의미를 갖는다. 데이터는 2.79M 전이(time 양성도 ~60k)라 불균형 학습이 가능할 수도 있다. 보정을 학습 후 후처리로 하는 것 vs 애초에 안 왜곡시키는 것 중 어느 쪽인가?
3. **causality 를 어떻게 다룰 것인가?** 약축 확정(8회 실패)인데 보정하면 신호의 절반을 차지한다. 축에서 빼는 것, ALPHA 로 누르는 것, 그대로 두는 것 중 무엇이며 근거는? (축을 빼면 5축 EISM 이라는 논문 주장 자체가 흔들린다는 점 고려)
4. **재학습이 개수 제어(2.4배 과분절)에 실제로 기여하나?** 위 아핀불변 논증대로면 임계 규칙을 안 바꾸는 한 기여가 없어 보인다. 그렇다면 재학습과 개수 제어(최소간격 NMS 등)는 **분리된 두 트랙**으로 봐야 하나, 아니면 순서가 있나?
5. **사전등록 설계**: 위 결정들을 검증하려면 어떤 조건 집합을 어떤 순서로 돌려야 하나? 무엇이 게이트이고 무엇이 탐색인가? 실패 판정 기준은?

답은 실행 가능한 결론 + 근거로. 애매하면 "모른다/추가 진단 필요"라고 하고 어떤 진단인지 적어줘.
