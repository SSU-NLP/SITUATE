# B1 모델 강건성 — 라벨러와 **동일 모델**로 재실행 (2026-07-31 KST)

러너 `scripts/eacl_phase0/b1_model_scale.py` · 산출 `b1_{label}.json`.
기존 표(ledger D-M11 부속 "B1 모델 강건성", Pieman 단독)의 **dev-3 3편 확장**.

## 1. 설정

외부 비판: *"M3-S5(Qwen3.6-35B) 대 B1(GPT-2-XL) 은 이론 대결이 아니라 모델 세대 대결이다."*
⇒ **B1 의 LM 을 M3-S5 라벨러와 문자 그대로 같은 모델(`/shared/models/Qwen3.6-35B-A3B`)로 바꿔** 재실행.

| 항목 | 값 |
|---|---|
| B1 절차 | Kumar et al. (2023) transient Bayesian surprise, `b1_bayes_surprise.py` **무수정** |
| readout · 규칙 | `newsent_max` · 적응 임계 μ+cσ, **c 는 pieman(dev) argmax 로 동결** — 기존 행과 동일 절차 |
| dtype / ctx | fp16 / 1024 토큰 이동 창 (기본값 유지) |
| 채점 | `hi_ontop.dts_scoring.score_dialogues` |
| 인프라 | transformers 4.49 가 `qwen3_5_moe` 미지원 ⇒ **동결 venv 를 건드리지 않고** 격리 경로에 5.14.1 설치 후 `PYTHONPATH` 로 주입 |

**🔒 회귀 확인 통과** — 새 하네스의 GPT-2-XL pieman = **0.3739**, ledger 기록값 **0.374** 재현.

## 3. 해석

**① ★ 세대 대결 프레임 종료.** 양팔의 LM 을 **같은 Qwen3.6-35B-A3B** 로 맞춰도 B1 의 문장 전이 AUC 는
**0.517 ~ 0.529 = 우연 수준**이다. M5 의 dev-3 AUC ~0.70 과의 격차는 **모델 세대가 아니라 방법**에서 온다.
1.5B → 35B 는 **23배**인데 AUC 는 오히려 **내려갔다**(0.533~0.563 → 0.517~0.529).

**② Score 는 올랐지만 순위력 때문이 아니다.** pooled 0.2836 → 0.3238(+0.040)인데 AUC 는 내려갔다.
이득의 출처는 **BOR** 이다 — 과분절이 4.67배 → 2.78배(tunnel), 2.63배 → 1.33배(monkey)로 줄었다.
큰 LM 은 서프라이즈 신호를 **평탄화**해 임계를 덜 넘게 만들 뿐, 경계를 더 잘 **구별하지는** 못한다.

**③ 그래도 무경계 하한은 넘는다.** 0.3238 > 0.2790. B1 이 완전히 무의미하지는 않다.

**④ 기존 서술과 일관.** *"Bayesian surprise 는 어느 문장 접합이 사건 경계인지 못 가린다 —
접합들이 서프라이즈에서 동질적이다"*(`b1_deployable.py` 문서화)가 35B 에서도 그대로다.

## 4. 판정

✅ **"약화된 베이스라인" 반론 종결.** 인용 문구:
> B1 의 LM 을 1.5B(GPT-2-XL)에서 우리 라벨러와 **동일한 35B 모델**로 교체해도 문장 전이 AUC 는
> 0.52~0.53(우연 수준)에 머문다. 스칼라 서프라이즈의 한계는 모델 용량이 아니라 방법이다.

## 4.5. 폐쇄 API 모델로도 B1 을 돌렸다 — 종전 "실행 불가" 판정의 **부분 철회**

ledger(D-M11 부속)는 *"B1 은 open logits 가 필요 → 폐쇄 API 로는 실행 불가"* 라고 적었다.
**이 판정은 GPT-5 계열에는 유효하고, GPT-4.1 에는 틀렸다.** 두 단계로 뚫었다.

### (가) top-k 절단이 신호를 보존하는지 먼저 측정 (`b1_topk_fidelity.py`)
API 는 top-20 logprobs 만 준다. 그래서 계산 가능한 것은 두 top-k 합집합 위에서 재정규화한 KL 뿐이다.
**전체 로짓을 가진 로컬 Qwen3.6-35B(pieman)에서 원 정의와 직접 대조:**

| 변형 | 단어 KL Spearman | 문장 신호 Spearman | Score (c=1.0) |
|---|---|---|---|
| 전체 어휘 (원 정의) | 1.0000 | 1.0000 | 0.4062 |
| top-5 | 0.9645 | 0.9294 | 0.3570 |
| **top-20 (API 상한)** | **0.9866** | **0.9736** | **0.4050** |
| top-100 | 0.9960 | 0.9935 | 0.4115 |
| top-1000 | 0.9996 | 0.9987 | 0.4130 |

⇒ **top-20 근사는 정당하다** (Score 차 −0.0012). top-5 는 부족하다(−0.049).

### (나) verbatim 복사 + logprobs 로 실행 (`b1_api_logprobs.py`)
문서를 그대로 복사시키고(temp 0) 생성 토큰마다 top-20 을 받는다. 복사가 원문과 일치하면
생성 위치 = 원문 위치가 된다. readout·임계·채점은 동결본 그대로.

| 모델 | 상태 |
|---|---|
| **GPT-4.1** | ✅ **실행됨.** verbatim coverage **100.0%** · char 정확도 100.0% (3편 전부, finish=stop) |
| GPT-5 / 5-mini / 5-nano | 🔴 **불가.** OpenAI 원문: `"logprobs are not supported with reasoning models."` (`unsupported_parameter`) — 추론 모델 전체에 걸린 provider 제약, 프롬프트로 우회 불가 |
| GPT-4o | 🔴 **거부.** 전문 복사 요청에 `"I'm sorry, I can't do that."` (8토큰, finish=stop). coverage 0.6% |
| gpt-oss-120b (API) | 🔴 `logprobs=True` 는 받지만 `top_logprobs` 가 **0개** 반환 |
| gpt-oss-120b (로컬) | 실행 중 — 가중치 로컬 보유(61GB mxfp4)라 **전체 어휘**로 가능 |

**GPT-4.1 결과** (top-20 근사, c=0.0 이 pieman argmax)

| doc | Score | AUC | pred | gold | BOR |
|---|---|---|---|---|---|
| pieman | 0.3188 | 0.5844 | 9 | 18 | 0.50 |
| tunnel | 0.2579 | 0.5935 | 114 | 18 | 6.33 |
| monkey | 0.2819 | 0.5359 | 80 | 30 | 2.67 |
| **pooled** | **0.2862** | 0.536 ~ 0.594 | | | |

⇒ **결론은 바뀌지 않는다.** GPT-4.1 의 B1 도 AUC 0.54~0.59 로 우연 근처이고, pooled 0.2862 는
GPT-2-XL(0.2836)과 사실상 동률이며 무경계 하한(0.2790)을 겨우 넘는다. **B1 의 천장은 프론티어
모델을 써도 오르지 않는다.**

## 5. 한계 (제거 금지)

1. **단어 해상도 AUC 는 이번에 재지 않았다.** Kumar 원 결과(word-res AUC ~0.70)는 기존 검증에서
   재현됐고, B1 의 실패는 **문장 접합 수준에 국한**된다는 기존 서술을 뒤집지 않는다.
   *"B1 은 아무것도 못 한다"* 로 인용 금지.
2. **c 를 pieman(dev) argmax 로 동결** — 기존 행과 절차를 맞추려 그대로 뒀으나, 이는 dev 선택이다.
   두 LM 이 서로 다른 c(0.75 vs 1.0)를 받았으므로 **작동점 차이가 Score 차이에 섞여 있다.**
   AUC 비교(작동점 무관)가 ①의 1차 근거다.
3. **fp16.** 원 스크립트는 KL 이 정밀도에 민감하다고 경고한다(`--fp32` 옵션 존재). 두 LM 모두 fp16 이라
   비교는 공정하나 절대값은 fp32 와 다를 수 있다.
4. Qwen2.5-7B/14B 행은 **pieman 단독 기록값**이라 pooled 열과 나란히 놓지 않았다.
5. dev-3 = 문서 3편. **봉인 시험지 미개봉.**
