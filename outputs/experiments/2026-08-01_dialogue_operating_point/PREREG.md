> 🔴 **이 문서는 결과를 보기 전에 작성됐다.** 아래 후보·지표·선택규칙·성공기준은 결과를 보고

## 0. 배경 — 왜 하나

D-B62(ψ 재개봉) 진단에서 나온 사실:

- `phase1_i2` 의 **인과축이 μ0.516 의 거의 상수 오프셋 + σ0.111 노이즈**로 합산 신호를 지배한다
  (dev-3 축별: 주인공 AUC 0.688 · 시간 0.685 · 공간 0.651 · **인과 0.622** · 의도 0.572).
- 그 노이즈가 합산 분포를 뾰족하게(첨도 0.916) 만들어 `μ+1.0σ` 적응임계의 컷 개수를 왜곡한다.
  인과축을 사슬로 교체한 `phase1_chainq_i2` 는 첨도 0.613 으로 정규에 가까워지고 컷이 9% 늘어,
  **신호는 더 좋은데(AUC 0.701→0.712) 적응임계 Score 는 떨어진다**(0.3974→0.3830).
- 밀도를 맞추면(고정분위수 BOR 1.02) chainq 가 Score·Pk·WD·L1 **전부** 이긴다.

⇒ **임계·신호조립 작동점이 라벨 품질 판정을 가리고 있다.** 작동점을 제대로 고른다.

## 1. 🔴 선택셋 — 앵커 절대 사용 금지

`phase0-decisions-and-runs.md:4736` **"앵커/의사-gold 에서 작동점 선택을 금지한다"** ·
D-B41 "앵커 선택셋 무효"(앵커엔 사람 경계 라벨이 없다) · `:5894` "작동점을 앵커에서 탐색 →
산출 폐기 + 코드 경로 차단".

**작동점의 정의(내가 틀렸던 지점을 명시한다):** 임계 규칙·c 계수뿐 아니라 **신호 조립 방식
(축별 z-score/순위 정규화, 축 가중치)** 도 작동점이다. *재학습 여부가 아니라 사람 경계에 맞추는
선택인가*가 기준이다. 앵커에서 골라도 되는 것은 모델 **구조·HP**(D-B29 격자)뿐이다.

- **선택셋 = DTS dev 3세트** (`dts_tiage` 20 · `dts_dialseg711` 12 · `dts_superseg` 15). 사람 gold.
- **확인셋 = DTS 공식 test** (`dts_full_*`) **에서 dev 와 내용이 겹치는 문서를 제외한 것**.
- **서사(dev-3)는 선택에 쓰지 않는다.** 확인용으로 병기만 한다(D-B41 §2: 서사 선택셋이 dev-3
  하나뿐이라 이미 보고셋 오염이 누적됐다 — 더 얹지 않는다).
- 이 배치가 정하는 것은 **대화 도메인 작동점 하나뿐**이다. 서사 작동점은 건드리지 않는다.

## 2. 모델 고정 — 작동점 선택에 모델 선택을 섞지 않는다

**`M5_phase1_i2_per_slot_slot_gsbook_pwone_seed0.pt`** 하나로만 고른다
(현행 구조 · 책 단위 분할로 학습 = 누수 없음 · psi none · head_feat delta).

`phase1_chainq_i2` 에는 **고른 작동점을 그대로 적용만** 하고 재선택하지 않는다. 라벨(i2 vs chainq)
선택은 별건이며 이 배치의 판정 대상이 아니다.

## 3. 후보 격자 (15조합)

**신호 조립** `s_t` — 문서 내에서 계산, 미래 정보 미사용:

| 이름 | 정의 |
|---|---|
| `raw` (현행) | `s = Σ_k P_k` |
| `zaxis` | `s = Σ_k (P_k − μ_k)/σ_k` (문서 내 축별 표준화) |
| `rankaxis` | `s = Σ_k rank(P_k)/(n−1)` (문서 내 축별 순위) |

**임계 규칙**:

| 이름 | 정의 |
|---|---|
| `pct` | 고정분위수 — 문서 내 상위 `ANCHOR_R=0.0642` (앵커 밀도 사전, gold 밀도 미사용) |
| `adapt_c0.5` / `adapt_c1.0`(현행) / `adapt_c1.5` / `adapt_c2.0` | `online_nf μ+cσ`, warmup 5 |

전부 `hi_ontop_v2.adaptive_boundaries` / 동결 채점기 직접 호출. 재구현 금지.

## 4. 🔒 선택 규칙 (사전 확정)

- **선택 지표 = DTS dev 3세트의 deployable Score 평균** 하나. AUC 는 보조로 기록만.
  (세트별 gold 밀도가 달라 열 간 비교는 안 하고, 조합 간 비교만 한다.)
- **argmax** 를 고른다.
- **동률 처리**: 1위와의 차이가 **0.01 미만**이면 동률로 보고 **더 단순한 쪽**을 택한다.
  단순 순서 = `raw` > `zaxis` > `rankaxis`, `adapt_c1.0`(현행) > `pct` > 그 외 c.
  ⇒ 현행 조합(`raw` + `adapt_c1.0`)이 1위와 0.01 안이면 **현행 유지**로 판정한다.
- **dev 3세트 중 2세트 이상에서 현행보다 나아야** 채택 후보가 된다(한 세트가 끌고 가는 것 방지).

## 5. 🔒 확인 (test 1회)

고른 조합 **1개만** 확인셋에 적용한다. 격자를 test 에서 다시 돌리지 않는다.

- **성공** = 확인셋 3세트 평균 Score 가 현행 조합보다 **개선** AND **3세트 중 2세트 이상 개선**.
- **실패** = 그 미만. 실패면 **현행 작동점 유지**로 기록하고 끝낸다. 기준을 낮추지 않는다.
- AMI 는 회의 2편·gold 11 이라 **선택·확인 어디에도 넣지 않는다**. 참고로만 병기하며
  채점은 `hi_ontop.ami_scoring`(±2 tolerant, 시작-turn)으로 한다.
- dev-3(서사)도 병기하되 **판정에 넣지 않는다**.

## 6. 한계 (미리 적는다)

- **seed 1개**(seed 0). 조합 간 차이가 seed 잡음 안일 수 있다. 채택되면 3-seed 확인이 남는다.
- dev 세트가 작다(20/12/15편). 0.01 미만 차이를 못 가른다 — 동률 규칙을 둔 이유다.
- 모델은 **서사 픽션으로만** 학습됐다(D-M8). 대화는 도메인 밖이며 절대값을 성능으로 인용하지 않는다.
- 이 배치는 **대화 작동점**만 정한다. 서사 작동점·라벨 선택(i2 vs chainq)은 별건으로 남는다.
