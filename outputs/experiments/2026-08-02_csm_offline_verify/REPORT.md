# CSM 오프라인 논문 재현 검증 — 온라인에 쓸 체크포인트 선정 (2026-08-02 KST)

## 1. 실험 setup

**목적.** 사용자 지시 — *"오프라인 CSM으로 했을 때 정확했던 학습본으로 온라인 돌려라."*
`outputs/experiments/2026-07-29_baseline_compare` 의 CSM 행(dev-3 0.2880)은 우리가 학습한
체크포인트를 **스트리밍으로 개조**한 판이고, **오프라인으로는 한 번도 채점된 적이 없었다.**
따라서 (a) 우리 학습본이 원논문 오프라인 성능을 재현하는지 확인하고, (b) 가장 잘 재현한
체크포인트를 골라 **그것으로 온라인 표를 다시 만든다.**

| 항목 | 값 |
|---|---|
| 러너 | `methods/CSM/offline/whole_dialogue.py` (SuperDialseg `CSMSegmenter`, whole-dialogue = 미래 포함) |
| 데이터 | Def-DTS 번들 **공식 test** — tiage 100 · dialseg711 711 · superseg 1322 대화 |
| 하이퍼 | `cut_rate(=α)=1.0 · max_utterance_len=50 · backbone=bert-base-uncased` — 전부 발표값(D-B41 부칙) |
| 후보 ckpt | 에폭 말 10개(`cpt_25905 … cpt_248145`) + devbest `cpt_108620` = **11개** |
| 미실행 | 240개 전 체크포인트 스윕은 하지 않았다(에폭 말만). 그 사이 구간은 알 수 없다 |
| 지표 | 러너 내장 = segeval Pk/WD + boundary-set F1, `Score = 0.5F1 + 0.25(1−Pk) + 0.25(1−WD)` |
| 대조 기준 | CSM 논문 오프라인(Jiang et al. 2023 SuperDialseg Table 3 인용, `outputs/reports/dts_result.md`) |
| 선택 규칙 | 🔒 **3셋 평균 오프라인 Score 최대** (실행 전 고정). 선택셋 = **CSM 자기 논문 벤치의 공식 test**, 우리 dev-3·시험지 아님 |

🔴 **하네스 주의.** 러너 지표는 5월 CSM 실행과 같은 계보(하네스 B)이고, 논문 인용값은
하네스 (C)다. 아래 %는 **다른 채점기 간 비율**이므로 ±수 % 는 채점기 차이일 수 있다.
main 표(`EACL/main_result.md`)의 채점은 이것과 별개로 **하네스 (A)** 로만 한다.

## 3. 해석

- ✅ **우리 학습본은 오프라인에서 논문을 재현한다** — tiage 84~105%, superseg 100~112%.
  11개 중 **6개**가 tiage 에서 논문값의 95% 이상, **11개 전부**가 superseg 에서 99% 이상이다.
- 🔴 **dialseg711 만 재현되지 않는다** (최대 76.6%). 이는 이번 학습본만의 문제가 아니다 —
  5월의 **배포 체크포인트**(`cpt_277000`)도 dialseg711 에서 논문 대비 **72%** 였다(D-B41 §5).
  즉 dialseg711 격차는 체크포인트가 아니라 **데이터·전처리 계보 차이**로 보인다. 미해명으로 남긴다.
- ⇒ **핵심 정정:** 기존 표에서 CSM 이 자명한 하한 근처였던 것은 **학습 실패가 아니다.**
  같은 체크포인트가 오프라인에서는 논문 수준을 낸다. 차이를 만든 것은 **스트리밍화**다
  (`2026-07-29_baseline_compare/REPORT.md` §5.4 가 예고한 "측정하지 않은 손실"이 여기서 측정됐다).
- 에폭에 따른 오프라인 Score 는 **단조롭지 않다**(0.4449~0.5019, 폭 0.057). D-B56 §5 의
  "체크포인트 선택이 판정을 바꾸지 못한다"는 **온라인 채점에서의 관찰**이며, 오프라인에서는
  선택에 따라 평균 0.057 이 움직인다.

## 4. 판정

**선택 = `cpt_175335`.** 이 체크포인트로 온라인(delay=2 · α=1.0 · min_gap=2)을 다시 돌려
main 표에 `CSM (오프라인 검증 ckpt)` 행으로 싣는다. 기존 `CSM`(최종 ckpt)·`CSM-devbest` 행은
**지우지 않고 병기**한다 — 세 선택 프로토콜이 모두 보고돼야 선택 효과를 읽을 수 있다.

## 5. 한계 / 검증 미해결

- **선택셋 = 공식 test.** 원저자 절차는 dev 부분집합에서 고르지만, 우리는 코퍼스를 건너
  전이시키므로 대응하는 dev 가 없다. 이 선택은 **baseline 에 유리한 방향**이며 그대로 공시한다.
- **하네스 B vs C 혼용** — 위 % 는 채점기가 다른 두 수치의 비율이다. 절대 재현 판정이 아니라
  *"같은 자릿수에서 재현되는가"* 수준으로만 읽어야 한다.
- **에폭 말 11점만** 봤다. 240점 전수 스윕은 하지 않았다.
- dialseg711 76% 의 원인 미규명 (데이터 계보 가설은 검증 안 됨).
- 오프라인 러너의 latency 는 비교 목적이 아니다(미래를 보는 설정).
