# API worker 측정 결과

수집·평가 worker 수를 4로 설정했다. GPU JOB 상한은 2이며 별개다. 이후 사용자 승인에 따라 본 실험 driver를 시작했다.

| Workers | 성공/시도 | 처리량 (요청/초) | 결과 |
|---|---:|---:|---|
| 1 | 4/4 | 0.0318 | 오류 없음 |
| 2 | 4/4 | 0.0529 | 오류 없음 |
| 4 | 8/8 | 0.0761 | 오류 없음 |
| 8 | 15/16 | 0.1366 | 60초 타임아웃 1건 |
| 8 재시험 | 6/8 | 0.1288 | 120초 제한, HTTP 429 2건 |

가상 기억 20개를 갱신하는 예문을 사용했다. 사용자·벤치마크 내용은 전송하지 않았다. 429 발생 시 새 요청을 중지하고 이미 시작한 요청만 회수했다. 제한이 계정의 요청 수·토큰 처리량에 의한 것인지 제공자의 동시성 제한인지는 확인되지 않았다. 4 workers의 처리량은 이 짧은 시험에서 1 대비 2.39배, 2 대비 1.44배였으며 실제 벤치마크의 속도 향상을 보장하지 않는다.

성공 응답에 보고된 두 시험 비용의 합은 $0.00862245이다. 실패 요청의 미보고 비용은 포함하지 않는다.

수집·평가는 한 프로세스에서 인코더를 공유하고 대화별 상태·비용·오류를 분리하도록 변경했다. 입력을 worker 수만큼만 읽는다. 병렬 격리 검사를 포함한 테스트 18개가 통과했다. workers.json을 driver가 읽어 수집·평가에 적용한다. 합성 생성도 현재 선택값 4를 사용한다. 공식 채점 모델의 동시성은 이 시험으로 검증하지 않았으므로 변경하지 않았다.

최초에는 자동 승인 검토가 새 제공자에 대한 전송을 차단했으며, 이후 사용자 진행 승인을 받고 본 실험을 시작했다.
