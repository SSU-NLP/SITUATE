## 1. 실험 setup

### 1.1 목적
Membox 의 **Topic Loom**(온라인 경계 판정기)을 우리 baseline 패널에 넣으려면 먼저 **우리 구현이
논문 방법인지** 확인해야 한다. 그런데 논문은 분절 지표를 일절 보고하지 않아(§1.5) **LoCoMo QA 가
유일한 검증 지점**이다. 그래서 메모리 시스템 전체를 재현해 논문 Table 1 과 대조한다.

### 1.2 🔴 공식 코드가 없다 — 1차 자료 = 부록 프롬프트 4장

2026-08-01 확인:

|---|---|---|

논문 본문·초록·comments 어디에도 저장소 URL 이 없고 저자 이메일만 있다.
⇒ **arXiv e-print LaTeX 소스에서 부록 프롬프트 4종을 전사**해 `scripts/segmentation_prompts/membox/`

### 1.3 데이터 · 지표

| 항목 | 값 |
|---|---|
| 데이터 | `benchmarks/locomo/locomo10.json` — 10 대화 · **5,882 메시지** |
| 문항 | **1,540** (카테고리 5 = adversarial 제외 — 정답 라벨 부재로 논문도 제외) |
| 카테고리 | 1 multi-hop 282 · 2 temporal 321 · 3 open-domain 96 · 4 single-hop 841 |
| 지표 | **F1**(토큰 집합 중첩) + BLEU-1 — `external/nemori/evaluation/locomo/metrics/utils.py` |
| 백본 | `openrouter/openai/gpt-4o-mini` (구축·QA 동일), temperature 0 |

**채점기 계보를 맞춘 것이 중요하다.** F1 은 토큰 중첩이라 **답변 장황도에 극도로 민감**하다.
Membox 가 대조한 Mem0 와 같은 계보의 채점기·답변 프롬프트를 쓰지 않으면 숫자가 비교 불가능해진다.
그래서 답변 프롬프트는 Mem0 계보(nemori `search.py::ANSWER_PROMPT`)를 그대로 쓰고,
episodic/semantic 2분할만 우리 메모리 구조에 맞게 1개로 합쳤다.

**Topic Loom 은 논문 안에서 독립 채점된 적이 없다.** 항상 QA 성능을 통한 간접 평가다.

### 1.6 🔴 논문 미명시 = 우리가 정한 것 (재현 불확실성의 소재)

| 항목 | 우리 결정 | 근거 |
|---|---|---|
| 연속성 출력 파싱 | "partial" 먼저 검사 → yes → no. 형식 이탈은 **봉인 + 별도 집계** | 미명시. 실측 이탈 **0건** |
| 박스 표현 임베딩 | 4필드(messages·topic·events·keywords)를 **한 문자열로 이어 단일 임베딩** | "박스 표현과의 유사도"라고만 서술 |
| `P_init` 출력 사상 | primary_chain 1 trace · secondary 각 1 · **isolated_events 각각 단일 trace** | 미명시. 버리면 정보 손실 |
| Trace 모드 후보 이벤트 | **검색된 top-10 박스의 이벤트** | "candidate events" 범위 미명시 |
| Compact 문맥 구성 | 박스의 topic + events + messages | "box content" 라고만 서술 |
| 검증 채택 | LLM 이 돌려준 `related_events` 중 **원문과 일치하는 것만** | LLM 재작성 방지 |

### 2.2 🔴 핵심 불일치 — Trace 확장 이득이 재현되지 않는다

| | multi-hop | temporal | open-domain | single-hop | 평균 |
|---|---|---|---|---|---|
| 우리 (trace − compact) | +0.53 | **−0.03** | **−0.44** | +0.05 | **+0.03** |
| 논문 (trace − compact) | +1.31 | +1.60 | +2.40 | +1.09 | **+1.60** |

**기구가 안 돈 것이 아니다** — 작동 여부를 따로 계측했다:

| 계측 | 값 |
|---|---|
| trace 가 1개 이상 부착된 문항 | **100.0%** (1,540/1,540) |
| 문항당 부착 trace 수 | 평균 **1.84** |
| 문맥 증가 | 12,483자 → 14,621자 (**+2,143자**) |
| 두 모드의 답변이 달라진 비율 | **29.6%** |

⇒ **trace 는 정상적으로 붙고 답변도 3할이 바뀌는데, 순이득이 0이다.**
논문의 중심 주장 중 macro-topic trace 층의 기여가 우리 재현에서는 **관측되지 않았다.**

#### 2.2.1 원인 추적 — 우리 구현의 퇴화가 아니다 (가설 2건 반증)

**가설 A: `P_init` 의 isolated_events 를 단일 trace 로 만든 것이 얇은 trace 를 양산했다.**
초판 trace 631개 중 **59.6% 가 단일 박스**에만 걸쳐 있어 유력해 보였다.
→ `--isolated drop` 으로 재구축·재평가(전 단계 재실행). **반증됨.**

| | trace 수 | 이벤트 평균 | 단일박스 | trace 이득(평균) |
|---|---|---|---|---|
| `singleton` (초판) | 631 | 4.64 | 59.6% | **+0.03** |
| `drop` (신판) | 580 | 4.85 | **58.4%** | **−0.43** |

구조가 거의 안 변했고(단일박스 −1.2%p) 이득은 **오히려 나빠졌다.** 단일박스 trace 의 원인은
isolated singleton 이 아니라, **생성된 trace 가 이후 박스에서 이벤트를 못 받는 것**이다.

**가설 B: trace 확장이 이미 검색된 박스의 이벤트를 되풀이해 새 정보가 없다.**
검색을 재현해 신규성을 직접 측정(임베딩만 사용, 1,540문항 전량). **반증됨.**

| 계측 | 값 |
|---|---|
| 문항당 붙은 trace | 1.83개 |
| 붙은 trace 의 이벤트 | 평균 **38.1개** |
| 그중 **검색된 박스에 없던 것** | 평균 **25.7개 → 신규율 67.6%** |
| 신규 이벤트가 0인 문항 | 16.5% |
| 붙은 trace 중 단일박스 | **17.5%** (전체 58.4% 대비 낮음 — 검색이 큰 trace 를 선호) |

**링크도 정상 작동한다** — 검증 통과로 추가 부착된 (trace, 박스) 쌍이 **1,069회**,
이벤트 있는 박스 861개당 **1.24회**다.

⇒ **기구는 설계대로 돌고, 문항당 25.7개의 새 이벤트를 실제로 공급한다. 그런데 F1 이 안 오른다.**
"우리 구현이 퇴화해서"라는 설명은 두 방향 모두에서 닫혔다.

### 2.3 ✅ 논문이 보고하지 않은 수치 — 연속성 라벨 분포

10 대화 4,965회 판정:

| 라벨 | 건수 | 전체 대비 | **봉인 중 비중** |
|---|---|---|---|
| continuous | 4,066 | 81.9% | — |
| **partial shift** | **874** | 17.6% | **97.2%** |
| **discontinuous** | **25** | **0.5%** | **2.8%** |
| 형식 이탈(unparsed) | 0 | 0.0% | — |

- 논문은 *"대부분의 전환이 discontinuity 가 아니라 partial shift 로 라벨링된다"* 고 **서술만 하고
  빈도표를 싣지 않았다.** 실측하니 정도가 "대부분"보다 극단적이다 — 대화당 discontinuous 는
  0~11건이고 conv-44 는 **0건**이다.
- **3분류로 설계됐지만 실질은 이진 분류기다.** 세 라벨 중 둘이 같은 동작(봉인)에 사상되고,
  그중 하나가 사실상 발화하지 않는다.
- ⚠️ 이는 **"Partially Shifted 선택지를 빼고 Yes/No 로 물어도 거의 같은 분절이 나오는가"** 라는
  값싼 ablation 을 시사한다. **미실행** — 실행 시 사전등록 후 별도 기록.

## 3. 해석

### 3.1 절대 수치의 −2~−5 는 "패턴은 맞고 절대값이 낮은" 형태다
8칸 전부 같은 방향으로 낮고, **카테고리 간 순서와 상대 크기는 논문과 일치한다**
(temporal ≫ multi-hop, single-hop 최상위권, open-domain 최하위). 즉 구조적으로 다른 것을 만든 것이
아니라 **같은 형태를 조금 약하게 만든 것**에 가깝다. 원인 후보는 §1.6 의 미명시 항목 6개와
답변 프롬프트 세부다. **어느 것이 원인인지 이 실험은 분리하지 못한다.**

### 3.2 Trace 이득 부재가 더 중요한 결과다
절대값 격차는 미명시 항목으로 설명될 여지가 있지만, **trace 이득은 논문 안의 대조**라
구현 상수의 영향을 덜 받는다. 같은 파이프라인·같은 검색 결과 위에 trace 만 얹은 차이이기 때문이다.
그런데 논문은 4/4 카테고리에서 +1.09~+2.40 을 보고하고 우리는 4/4 에서 **−0.44~+0.53** 이다.

§2.2.1 이 두 가지를 닫았다 — **trace 는 얇지 않고**(붙는 trace 의 82.5%가 cross-box),
**중복도 아니다**(신규율 67.6%, 문항당 새 이벤트 25.7개). 그런데도 이득이 0이다.

남은 해석은 **"새 정보이긴 한데 도움이 안 되는 정보"** 다. 문항당 38.1개 이벤트가 한꺼번에
붙는데(문맥 +2,143자), LoCoMo 질문은 대개 사실 1~2개만 필요하다. 답변의 29.6%가 바뀌고
순이득이 0이라는 것은 **이득 본 문항과 손해 본 문항이 상쇄됐다**는 뜻이며, 이는 희석(dilution)의
전형적 서명이다. 즉 우리 재현에서 Trace Weaver 는 **정밀도 없이 재현율만 올리는 확장**이 됐다.

🔴 **그래도 "논문이 틀렸다"로 읽지 않는다.** 우리가 재보지 않은 자유도가 남아 있다 —
trace 를 문맥에 넣는 **표현 형식**(우리는 이벤트를 `->` 로 이은 한 줄), 이벤트 top-2 의
**후보 범위**(우리는 검색된 박스 내부), trace 이벤트의 **개수 상한**(우리는 무제한 — 최대 79개짜리
trace 가 통째로 들어간다). 논문은 셋 다 명시하지 않는다. 특히 마지막 항목은 희석 가설과 직결된다.

### 3.3 Topic Loom 은 대화 무대에서 경계율 15% 대로 분절한다
메시지당 박스 0.155 는 우리 DTS 대화 벤치마크의 gold 경계율(14.8~25.1%)과 같은 대역이고,
서사 dev-3(6.57%)의 **2.4배**다. 이 판정기를 서사에 얹으면 과분절이 예상되며, 이는 §2.5 의 다른
대화용 baseline 들이 보인 패턴과 같다. **미측정 — 서사 이식은 별도 실행이다.**

## 5. 한계 / 검증 미해결 (제거 금지)

### 5.1 🔴 이 재현으로 "우리가 Membox 를 정확히 구현했다"고 말할 수 없다
절대값이 8칸 전부 낮고 **논문 내부 대조(trace 이득)가 뒤집힌다.** 구현 오류인지, 미명시 항목의
선택 차이인지, 논문 수치의 재현성 문제인지 **이 실험은 분리하지 못한다.**
⇒ Topic Loom 을 우리 baseline 표에 넣을 경우 **"우리 이식판이며 원 논문 수치와 대응하지 않는다"**
를 반드시 병기한다. 이는 §2.5 의 다른 baseline 에 적용한 규칙과 같다.

### 5.2 미명시 항목이 부분적으로만 통제됐다
§1.6 표의 6개 중 **애블레이션한 것은 1개**(`P_init` isolated 처리, §2.2.1 가설 A)이고,
**측정으로 배제한 것이 2개**(연속성 파싱 = 이탈 0건 · 확장 중복 = 신규율 67.6%).
나머지 3개(박스 임베딩 결합 · Compact 문맥 구성 · 검증 채택 규칙)와, §3.2 에서 새로 식별한
**trace 이벤트 개수 상한**은 **미통제**로 남는다. 상한 항목은 희석 가설과 직결되나
논문에 근거가 없어 재현 범위에서 제외했다(§4).

### 5.2.1 🔴 "이득 미재현" 판정의 사정거리
확정한 것은 **"우리 구현에서 Trace 확장이 F1 을 올리지 못했다"** 이고, 그 실패가
**얇은 trace·중복 확장 때문은 아니다**까지다. **논문의 +1.60 이 재현 불가능하다는 주장이 아니다** —
미통제 자유도 4개가 남아 있고, 특히 이벤트 상한이 다르면 결과가 달라질 수 있다.
논문 저자들 자신도 Mem0/A-MEM 재구현에서 원 인용값 대비 **temporal −14점**을 기록했다
(Table 1 의 `Mem0*` 48.93→34.52 · `A-MEM*` 45.85→29.14). **메모리 시스템 재현이 원 수치에
못 미치는 것은 이 논문 안에서도 이미 일어난 일**이며, 우리 −2~−5 는 그 3분의 1 수준이다.

### 5.3 백본 1종 · 1회 실행
gpt-4o-mini 단일, temperature 0, 반복 없음. LLM 판정의 run 간 변동을 모른다.
논문도 반복 횟수를 밝히지 않았다.

### 5.4 채점기가 토큰 **집합** F1 이다
`calculate_metrics` 는 `set(tokenize(...))` 로 중복을 무시한다(표준 SQuAD 의 다중집합 F1 과 다름).
Mem0 계보 구현을 그대로 쓴 것이라 **Membox 가 대조한 Mem0 와는 같은 조건**이지만,
논문이 실제로 이 구현을 썼는지는 확인할 수 없다.

### 5.5 답변 프롬프트가 논문 것이 아니다
논문은 "원 벤치마크 프롬프트를 따른다"고만 밝히고 부록에 싣지 않았다. 우리는 Mem0 계보 프롬프트를
썼고 episodic/semantic 2분할을 1개로 합쳤다. **F1 은 답변 장황도에 민감하므로 이 선택이
절대값에 직접 영향을 준다.**

### 5.6 baseline(Mem0/A-MEM)을 우리가 돌리지 않았다
논문은 저자들이 직접 배포해 검색깊이 k∈{5,10,20,30} 중 **최고점**을 보고했고 Membox 는 k=10 고정이다.
우리는 Membox 만 돌렸으므로 **이 비대칭이 우리 표에는 반영되지 않았다.**

### 5.7 LoCoMo 다운스트림은 원래 미루기로 한 트랙이다
사건 단위 retrieve→QA 는 M4~M7 이후로 미룬 결정이 있다. 이 실행은 **Membox 구현 검증 목적**에
한정되며, 우리 방법의 다운스트림 성능 주장으로 쓰지 않는다.
