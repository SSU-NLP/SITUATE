# EM-LLM 다운스트림 검증표 — 논문 세대 체크포인트 (M5 · M4 · M8-pair)

**상태: 3 arm 전부 완주·채점 완료** (M5 13:40 · M4 16:18 · M8-pair 18:40 KST, 각 3,550/3,550 머지 무손실).

실행 경위: NarrativeQA 우위를 유의하게 만들려면 서사 표본이 더 필요해(§2.2) ∞-Bench En.QA 로
전환을 시도했으나(추정 57 GPU시간 / 밤샘 런), 사용자 결정으로 **LongBench 범위로 되돌리고
M8-pair 를 재개**했다. En.QA 는 산출 0건 상태에서 중단해 낭비가 없다 — 서사 표본 부족은
**미해결로 남는다**(§5).

## 1. 실험 setup

### 목적
`EACL_Paper.tex` 의 EM-LLM 다운스트림 표는 **2026-07-31 세대 M5 단일 체크포인트** 하나뿐이고
M4·M8 이 없다. 반면 논문 본문 Table 1(`tab:per-work`)은 **2026-08-03/04 세대**(D-B70)로 돌았다.
이 불일치는 `outputs/experiments/2026-08-04_i2_all_models/REPORT.md:153-154` 에 미결로 적혀 있었다.
본 실험은 **논문 세대 체크포인트로 하류 검증표를 다시 만든다.**

### 데이터
LongBench 15 태스크 **3,550건** (`/shared/emllm/data/longbench`).
`narrativeqa · qasper · multifieldqa_en · hotpotqa · 2wikimqa · musique · gov_report · qmsum ·
multi_news · trec · triviaqa · samsum · passage_retrieval_en · lcc · repobench-p`

### 하류 시스템 (고정 — 전 arm 동일)
| 항목 | 값 |
|---|---|
| base LLM | `meta-llama/Llama-3.1-8B-Instruct` (greedy, 배치 1 고정 `greedy_search.py:82`) |

| 채점 | LongBench 공식 `benchmark/eval.py` (`metrics.py:calc_score`) |

제약디코딩) 없음** — `min_blk`/`max_blk` 가 없어 `pred.py:387-391` 어댑터 분기를 타지 않는다.

### 분절기 (논문 세대)
| arm | em_splitter | 체크포인트 | md5 |
|---|---|---|---|
| `m5_paper` | `m5` | `M5_phase1__personkey_i2_per_slot_gsauthor_ep100_i2e100_seed0.pt` | `8e432a6c` |
| `m4_paper` | `m4` | `M4_phase1__personkey_i2_per_slot_gsauthor_ep100_i2e100_seed0.pt` | `ec6e0143` |
| `m8pair_paper` | `m8_pair` | `2026-07-31_m8_direct_boundary__personkey_i2_e100/M8_pair_seed0.pt` | `fe611662` |

**작동점 = 적응임계 `online_nf`, c=1.0** — `s_t ≥ 누적평균(s_<t) + 1.0·누적표준편차(s_<t)`.
미래 미사용 · gold 개수 미사용. **세 arm 모두 동일**하며 M8 도 같은 `adaptive_boundaries` 를 탄다
(`m8_default.py:116`). 신호만 다르다: M4/M5 는 `s = Σ_k P(reset_k)`, M8 은 `s = P(boundary)`.

🔴 **작동점 정정 (2026-08-04)**: 논문 초고는 "top 6.60% of transitions within each document" 로
적혀 있었다. 그 규칙은 전이 t 를 판정하는 데 t+1..T 가 필요해 **오프라인**이며 Hi-OnTop 의
온라인 주장과 어긋난다(D-E25 에서 이미 지적). 본문·Table 1·하류 arm 을 전부 적응임계로 통일했다.

### 학습 설정 (논문 세대 = D-B70)
앵커 11,836편 / 3,013,224 전이 / 경계율 0.0657 · **author-level split** 10,430 train / 1,406 val
(구 `--group-split none` 은 val 의 96.1% 가 train 과 저자를 공유했다) ·
M4/M5 Adam lr 3e-4 batch 48 slot_dim 128, M8 batch 8192 · **epochs 100 + val-loss early stopping
(patience 3)** · 하류는 **seed 0 단일**(상류 Table 1 은 4 seed 평균).

- `m5_splitter.py` / `pred.py` / `greedy_search.py` 에 `m4`·`m8_pair` 허용 추가

- `pred.py:552` 경쟁 조건 수정 — 아래 §5 참조.

## 3. 해석

**(1) 상류 개선이 하류로 전이되지 않는다 — 이번 실험의 핵심 결과.**
논문 세대 체크포인트는 앵커 재구축·author split·early stopping 으로 상류를 손봤는데
하류는 ★ 51.77 → 51.47 로 **유의하게 내려갔다**(CI 상한 −0.07). 같은 규칙·같은 입도
(유효블록 83.8 vs 83.0, 건당 블록 101.2 vs 102.0)에서 나온 차이라 **입도 교란이 없다.**
이로써 "같은 규칙·다른 체크포인트" arm 이 **넷 다 ★ 아래**가 됐다:

| ckpt 세대 | 하류 평균 |
|---|---|
| ★ 2026-07-30 | 51.77 |
| **논문 2026-08-03/04** | **51.47** |
| i2 2026-07-31 | 51.27 |
| d44 | 51.06 |

**(2) 경계 위치 기여는 또 귀무다.** 무작위 대조 대비 +0.10 [−0.28, +0.49].
밀도가 3% 이내로 매칭돼(101.2 vs 98.6) 위치만 다른 비교인데도 구분되지 않는다.
D-L09 가 6조건 집계로 "M5 경계 위치가 EM-LLM 성능에 기여한다"를 **재현 실패**로 확정했고,
이번이 **일곱 번째 조건이자 같은 결론**이다.

**(3) 기준선을 이겼다고 말할 수 없다.** −0.24 는 노이즈 안이므로 "EM-LLM_S 보다 나쁘다"는
주장도 성립하지 않는다. 성립하는 진술은 **"넘지 못했다"** 뿐이다. ★ 의 +0.06 도 원래
[−0.32, +0.43] 로 구분되지 않았다 — **★ 조차 기준선을 이긴 적이 없다.**

**(4) 분절 자체는 값어치가 있다.** `surprisal vs 분절없음` +0.52 [+0.16, +0.89] 는 구분된다.
즉 구도는 "분절이 무용하다"가 아니라 **"우리 분절이 surprisal 보다 낫다는 증거가 없다"** 이다.

**(5) 🔴 상류 순위가 하류에서 뒤집힌다 — 이번 3 arm 이 새로 준 결과.**
상류 `tab:main` 에서는 축을 버린 Direct-Boundary(M8-pair)가 앞섰다(Score 0.394 vs SITUATE 0.376).
그런데 하류에서는 **M8-pair 가 51.37 로 셋 중 꼴찌이고 무작위 대조(51.36)와 사실상 동률**이다.
설명은 §2.1 의 지표에 있다: 상류에서 M8 이 이긴 이유는 순위력이 아니라(AUC 네 모델 동률
0.655~0.661) **과분절이 덜해서**였다(BOR 1.50 vs 2.17). EM-LLM 은 `max_block_size=128` 이
초과분을 어차피 잘라내므로 그 이점이 사라진다. ⇒ **상류 Score 우위는 하류로 전이되지 않는다.**
다만 세 방법의 하류 차이(±0.10)는 전부 노이즈 안이므로 "M8 이 하류에서 나쁘다"고 주장할 수는 없다.

**(6) 서사 축 패턴은 유지되나 상쇄된다.** NarrQA +1.32 로 최대 이득이지만
PsgRet −2.00 · MuSiQue −1.85 · Hotpot −1.11 이 그보다 크다. 이 비대칭 자체는
D-I16(∞-Bench En.QA 사전등록)에서 이미 다루는 별도 가설이다.

## 4. 판정

- **M5 [논문 ckpt]**: 사전등록 두 기준 모두 **미달**. 검증표에 그대로 싣되
  "기준선을 유의하게 넘지 못함"으로 적는다. 기준을 사후에 고치지 않는다.
- 논문 4번째 문단 제목 *"Replacing the segmentation module with Hi-OnTop **improves**
  downstream memory performance"* 는 **근거와 반대**다(`pipeline-overview-ko.md:612-613`,
  D-L09). 제목 교체가 필요하나 **사용자 확인 대상**으로 남긴다.
- M4·M8-pair 결과가 나오면 "축 분해가 하류로 전이되는가"(상류 Table 1 에서는 M8 이 앞섰다)를
  추가로 판정한다.

## 5. 한계 / 검증 미해결 (제거 금지)

1. **seed 1개.** 하류 arm 은 전부 seed 0 단일이다. 상류 Table 1 은 4 seed 평균이라
   **상류·하류의 불확실성 크기가 다르다.** 부트스트랩 CI 는 **샘플 뽑기 운만** 잡고
   체크포인트 seed 분산은 포함하지 않는다 — 실제 불확실성은 보고된 CI 보다 크다.
2. **입도 격차는 여전히 통제되지 않았다.** 우리 분절(유효블록 ~84)과 surprisal(~16)은
   설계점이 한 자릿수 다르다(D-E23). 기준선 대비 비교는 "위치"가 아니라
   "위치+입도" 를 함께 잰다. 무작위 대조 비교만이 입도가 통제된 비교다.
3. **`max_block_size=128` 강제분할.** 우리 경계로 만든 세그먼트의 상당 부분이 상한에 걸려
   임의 오프셋에서 잘린다(★ 기준 토큰의 43.9%). 이 harness 제약 하에서의 결과다.
4. **M4 arm 의 `em_splitter` 는 `m4` 지만 내부 경로는 `m5` 와 동일**하다(같은 FactoredSlot,
   같은 점수식). arm 을 가르는 것은 체크포인트뿐이다 — 코드 경로 차이가 아니다.
5. **M8 은 pair 변형만** 돌린다(사용자 결정). 논문 Table 1 의 M8 도 pair 로 맞췄다.
   ctx 변형의 하류 성능은 미측정이다.
6. **M8 의 이진 라벨은 M5 의 5축 리셋 라벨에서 파생**된다(`train_direct_boundary.py:328`,
   `resets.sum(1) >= T_STAR=3`). 완전히 독립적인 신호가 아니다.
7. **∞-Bench 는 이번 범위 밖.** 서사 축 가설(D-I16 En.QA 사전등록)은 별도 트랙이다.
8. **ConStory-Bench 는 기존 harness 로 불가.** 판정은 `DECISION_JOURNAL.md` D-P02 참조 —
   긴 텍스트가 입력이 아니라 **생성 출력**이라 분절할 입력 컨텍스트가 없다. 생성 시점 분절
   harness 를 새로 만들어야 하며 별도 사전등록 대상이다.
