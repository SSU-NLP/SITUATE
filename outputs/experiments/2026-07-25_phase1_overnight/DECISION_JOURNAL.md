## 결정 로그

### D-01 (수집 전) — Stage-1 토큰 예약 8000 → 2000
- **왜:** ami 두 번째 문서에서 `BadRequestError` — 입력 8,385 + 출력 예약 8,000 = 16,385 >
  max-model-len 16,384. Stage-1 은 편 전체를 넣으므로 우리 코퍼스(최대 700문장)에 그대로 온다.
  스모크 18편 기준 기본값 8000 이면 **22%(4/18)가 실패**, 2000 이면 0%.
- **대안:** 서버 `--max-model-len` 상향(재시작 필요·KV 벽 하락·측정 baseline 변경) / 길이 상한 축소
  (사용자 지정 30~700 위반).
- **되돌리기:** 인자 하나. Stage-1 출력은 엔티티 목록뿐이라 2000 으로도 과분하다.

### D-02 (수집 전) — 컨텍스트 초과 편은 동결 스크립트가 아니라 변환기에서 배제

- **한계:** 추정치 기반이라 경계선 편이 런 중 실패할 수 있다. 실패 시 해당 편만 건너뛰고 계속.
- **되돌리기:** 가능(제외 편 목록이 로그에 남음).

### D-06 (수집 중) — 분할기 결함 3건 수정 (스모크에서 발견)
- ① 章 번호(`XXIII`, `PART SECOND`)를 편 제목으로 오인 → `STRUCT_HEAD` 로 배제, 章 헤딩이 다수인

### D-07 (수집 완료) — 8,000편 정확히 도달, 후보 712권 미사용
- 원시 24,044편 → 길이필터 −6,939 · 중앙어휘수 −45 · 중복제목 −91 · **작가상한 −8,963** = 8,000.
- **작가 상한이 길이필터보다 더 많이 잘랐다.** 이미 받은 2,945권 안에 필터 통과 가능 편이
  약 16,969개 있으므로, 1만 편은 **다운로드 없이 상한만 올리면** 가능(파싱 5~10분).
- **SF 비율 46% → 22.2%로 자연 감소**(SF 권은 단일 중편이 많아 single/길이필터에 더 걸림).
  층화 안 한 결정이 결과적으로 유리했으나 **의도한 것 아님 — 관찰**. 메타 저장돼 사후 추출 가능.
- 사용자가 "1만편 안 되나" 물었으나 취침 전 확답 없었음 → **기존 결정 8,000 유지**하고 진행.
  근거: 본인이 "8k vs 10k 차이 없음"을 논거와 함께 정했고, 캐시가 살아 있어 후속 런 증량이 싸다.

### 🔴 D-16 (견적 정정) — 20시간 → **약 32시간**
- 최초 견적 20시간은 **편당 100문장 가정**이었다. 실제 중앙 215문장.

- **아침 보고 시점에 완료되지 않는다.** 부분 산출은 축별 캐시로 계속 쌓이고 resume-safe.

### D-17 (실행 구조) — 문서별 프로세스 → **64 샤드**
- 7,722문서 × 5축 = 38,610 작업을 문서별로 띄우면 파이썬 기동 오버헤드가 지배적.

### 🔴 D-18 (실패) — Stage-1 JSON 절단으로 샤드 전체 사망 (shard35)
- **증상:** `[FAIL] shard35 protagonist` — `JSONDecodeError: Expecting value: line 324 column 15 (char 5069)`.
  샤드 120문서 중 **2개만 처리하고 사망**. 진짜 손상은 문서 1개가 아니라 나머지 118개다.
- **원인 = D-01 의 반대급부.** `--stage1-max-tokens` 를 8000→2000 으로 내려 컨텍스트 초과는 막았으나,
  엔티티가 많은 문서에서 Stage-1 **출력이 절단**돼 JSON 이 깨진다. 양쪽 함정:
  · 8000 → 입력+출력 > max-model-len → 400 BadRequest
  · 2000 → 목록 절단 → JSONDecodeError
  중간값으로 올리면 입력 예산이 줄어 이미 포함된 문서가 다시 초과된다(순환).
- **처리:** `resilient_shard.sh` 신설 — 실패 시 **문제 문서를 특정해 샤드에서 빼고 재시도**하는 루프.
  검출법: Stage-1 성공 시 `{doc}/story_lists.json` 이 생기므로, "샤드 순서상 아직 없는 첫 문서"가 범인.
  건너뛴 문서는 `_skipped.log` 에 시각·샤드·축과 함께 기록(집계 가능).
- **동결본 미수정** — 래퍼 레벨 처리.
- **⚠️ 남은 위험:** 다른 샤드에서도 재발할 수 있고, 지금 도는 63개 프로세스는 **옛 드라이버**라
  같은 방식으로 죽는다. 죽는 즉시 감시가 알리며, 죽은 샤드는 resilient 래퍼로 재실행한다.
  (전부 resume-safe — 이미 끝난 문서는 캐시에서 건너뛴다.)
