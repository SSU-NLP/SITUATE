## 1. 실험 setup

### 1.1 목적
우리 방법(M5-FactoredSlot)을 **`Hi-OnTop/methods/` 의 기존 분절 baseline**, **supervised baseline**,
**LLM baseline** 과 **같은 채점기·같은 gold·같은 배포규약**으로 비교한다. 이전까지 우리 수치와
`methods/` 수치는 **서로 다른 채점기**에서 나온 것이라 한 표에 둘 수 없었다(§1.6).

### 1.3 비교 방법 목록

**우리 것 (온라인 · LLM-free)**
- **M5-FactoredSlot** — 5 타입 슬롯, `slot_dim=128`, dynamics `per_slot`, pred_space `slot`,
  체크포인트 `M5_per_slot_slot_seed0.pt`(앵커 10,069편 학습), 신호 `s = Σ_k P(reset_k)`.
- **M4-MonoAnchor** — 동일 학습·동일 신호, 슬롯 분리만 제거한 monolithic 대조.
- **M1-CosDrift** — δ_eff (`m=2, ρ=0.7, a=0.5`, registry §2 canonical), 같은 인코더.

**`methods/` baseline (전부 온라인 스트리밍 `push(utterance) -> list[int]`)**
- **TextTiling** — `hi_ontop.baselines.texttiling_streaming.StreamingTextTiling`
- **GraphSeg** — `hi_ontop.baselines.graphseg_window.GraphSegWindowD` (윈도 D 온라인 적응판, GloVe)
- **GreedySeg** — `hi_ontop.baselines.greedyseg_delay2.GreedySegOnlineDelay2`
- **CSM** — `hi_ontop.baselines.csm_online.CSMOnlineDelay2`, **우리가 직접 학습한 체크포인트**(§5.1)

**supervised baseline**
- **RoBERTa** — `methods/RoBERTa/`, SuperDialseg(EMNLP 2023) Table 3 `RoBERTa` 재현.
  superseg/train 학습, superseg/validation 으로 epoch 선택. 표에는 `predict_online` 스트리밍판.

**LLM baseline (SeCom 계열 binary, 온라인)**
- **SeCom-binary (무상태)** — `scripts/segmentation_prompts/baseline_segment_binary_narrative_v1.md`
- **SeCom-binary-stateful** — `..._binary_stateful_narrative_v1.md`, 자기가 이미 확정한 경계를
  `[Segment N | Sentence M]:` 로 문맥에 함께 제시
- 모델 `openrouter/openai/gpt-4o`, `temperature=0`, `max_tokens=4`, past = **full**

**제외 — 오프라인은 경쟁상대가 아니다.** `baseline_segment_v1.md`(SeCom 원본 partition)은
입력 전체를 한 번에 보고 자르는 **오프라인**이라 넣지 않았다. 우리 주장이 *온라인·실시간*이므로
미래를 보는 방법과의 비교는 성립하지 않는다. baseline 4종도 전부 원논문의 오프라인 추론
(전 문서 depth score + 전역 임계)을 **스트리밍으로 바꾼 판**을 쓴다(§5.4 — 이것 자체가 변형이다).

### 1.4 배포 규약 (deployable · 필수)
**어떤 방법에도 gold 경계 개수를 주지 않는다.** matched@gold / top-N 없음.
- M5·M4·M1 : 문서 내 고정분위수 **r = 0.0642** — 🔒 **앵커 val 5-fold OOF 가 고른 값**(D-B29/D-B30).
  dev-3 는 이 선택에 쓰이지 않았다.
- baseline 4종 : 각 원논문의 자체 적응 임계(running mean ± α·std 등)를 스트리밍으로 유지.
- RoBERTa : 토큰 분류 argmax — 개수 제약 없음.
- LLM 2종 : 매 문장 NEW/SAME 을 LLM 이 직접 판정 → 개수를 LLM 이 스스로 정한다.

### 1.5 🔒 baseline 작동점 동결 (D-B41, 2026-07-30)

"baseline 이 약한 게 하이퍼 탓 아니냐"를 닫기 위해 **모든 baseline 하이퍼를 SuperDialseg 원 구현과
1:1 대조**하고, 우리가 정한 것만 선택셋에서 탐색한 뒤 **동결**했다.

**출처 감사 결과** — GreedySeg 상수 5개, GraphSeg 2개, TextTiling 3개는 **발표값과 정확히 일치**.
우리가 정한 것은 CSM 의 α 와 스트리밍 노브 3개(delay·min_gap·warmup)뿐이었다.

| 도메인 | 방법 | 동결 작동점 | 출처 | 탐색 이득 ΔScore |
|---|---|---|---|---|
| 서사(dev-3) | TextTiling | `min_gap=4, warmup_gaps=3` | =발표값 | **0.0000** (발표값이 그리드 1위) |
| 서사 | GraphSeg | `window_d=10` | =발표값 | — (§ 아래 주) |
| 서사 | GreedySeg | 발표값 그대로 | =발표값 | 탐색 대상 없음 |
| 서사 | CSM | `alpha=1.0, delay=2, min_gap=2` | α=발표값, 나머지=우리 스트리밍 규약 | 탐색 안 함(부칙) |
| 대화(DTS) | TextTiling | `min_gap=2, warmup_gaps=3` | 탐색 | **+0.0013** |
| 대화 | GraphSeg | `window_d=10` | =발표값(그리드 1위) | **0.0000** |
| 대화 | GreedySeg | 발표값 그대로 | =발표값 | 탐색 대상 없음 |
| 대화 | CSM | `alpha=1.0, delay=2, min_gap=2` | 동일 | 탐색 안 함 |

**선택셋** — 서사 = **dev-3**, 대화 = **superseg/validation 앞 60대화**(732 전이).
🔴 **앵커 코퍼스는 선택에 쓰지 않았다.** 앵커는 S5 LLM 축별 리셋 라벨에서 만든 `count≥t*=3`
**의사-gold** 이지 인간 경계 라벨이 아니다. 작업 도중 앵커에서 고르는 코드를 한 번 돌렸고,
그 산출은 **전량 폐기**했으며 코드 경로 자체를 `SystemExit` 으로 막았다
(`baseline_opt_freeze.py::load_narrative`).

**주 — GraphSeg 서사 그리드 1위는 채택하지 않았다.** `window_d=5` 가 Score 0.2790 으로 1위였는데,
그건 **경계를 0개 찍어 무경계 하한과 완전히 같은 값**이다. 퇴화해서 얻은 점수라 "더 좋은 작동점"이
아니다. 사후에 배제 규칙을 새로 만드는 대신 **발표값 `window_d=10`(0.2212)을 그대로 쓴다** —
결과가 baseline 에 불리해도 그렇게 한다.

**부칙 — CSM 의 α 는 탐색하지 않는다.** 다른 baseline 의 발표값을 고정해 두고 CSM 만 탐색하면
비교가 비대칭이 된다. α=1.0 은 SuperDialseg 재구현의 `cut_rate=1.0` 이자 우리 이전 런
(`2026-05-24_csm_online_delay2_fixed/REPORT.md`)이 쓴 값이다. 코드 기본값이 `0.0` 이었던 것은
**폐기된 버그 런의 잔재**라 1.0 으로 정정했다(`src/hi_ontop/baselines/csm_online.py`).

**결론: 작동점은 어느 데이터셋에서도 baseline 약세의 원인이 아니다** (최대 이득 +0.0013).

### 1.6 지표
**Score = 0.5·F1 + 0.25·(1−Pk) + 0.25·(1−WD)**, `hi_ontop.dts_scoring.score_dialogues` 직접 호출.

### 1.7 🔴 채점기 세 개 문제 (이 실험이 만들어진 이유)
동일 gold·동일 예측을 두 채점기로 재보니 **ΔScore = 0.045**
(Pk 0.4446 vs 0.4192 · WD 0.4829 vs 0.4568 · F1 0.2087 vs 0.2729)였다.
우리가 재려는 효과(M5−M4 = 0.025)**보다 크다.**

- **(A)** `hi_ontop.dts_scoring` = SuperDialseg 공식 `SegmentationEvaluation`. **CLAUDE.md 가 강제.**
- **(B)** `methods/` online 쪽 = `segeval` 직접 + per-dialogue macro mean.
- **(C)** 공식 SuperDialseg window 규칙(= 평균 세그먼트 길이 ÷ 2). RoBERTa 원 REPORT 가 쓴 것.

**주 표 하네스 = (A) 로 사전 고정**했다(유리한 쪽 고르기 금지). (B)는 하네스 차이 진단용
**브릿지로만** 병기. **(C) 및 논문 인용 수치(Jiang et al. 2023 Table 3 등)는 이 표에 넣지 않는다.**
RoBERTa 의 (C) 수치는 §5.9 에 논문 대조용으로만 따로 둔다.

**예측 파일이 원자료다.** 전 방법이 `preds/<method>_<dataset>.json` 에 전이별 0/1 을 덤프한다
→ 언제든 재채점·감사 가능. 실제로 이 REPORT 작성 중 `results.json` 이 부분 재실행에 덮어써진
사고가 있었는데(§5.3) 예측 파일이 있어 손실 없이 복구했다.

### 1.8 seed
M5/M4 는 이 표에서 **seed 0 단일**이다. 3-seed 값은 D-B30 에서 별도 측정:
M5 dev-3 **0.4191 ± 0.0037**, M4 **0.3944 ± 0.0072**. 이 표의 seed-0 값(0.4190 / 0.3861)은
M5 는 평균과 사실상 같고 **M4 는 평균보다 0.008 낮은 쪽**이다 — M5−M4 격차를 읽을 땐 3-seed
값(Δ +0.0248)을 쓴다. RoBERTa 는 4-seed 를 측정했다(§5.9). baseline 4종은 결정적이다.

## 2.5 🔒 전 지표표 — Score · BOR · purity · coverage · F(p,c) · L1 (2026-08-01 추가)

**Score 단독으로는 밀도 효과와 신호 품질이 섞인다.** 그래서 6지표로 편다.
지표 정의는 **재구현하지 않고 프로젝트 동결 구현을 import** 했다
(`scripts/eacl_phase0/preds_table.py` → `full_comparison_dev3.{purity_coverage,lift_l1}` ·
`hi_ontop.dts_scoring`). 원자료 = `preds/*.json`, 집계 = `preds_table.json`.

| 지표 | 뜻 | 읽는 법 |
|---|---|---|
| **Score** | 0.5·F1 + 0.25·(1−Pk) + 0.25·(1−WD) | 주지표. 자명한 하한과 비교해야 의미가 있다 |
| **BOR** | 예측 경계 수 / gold 경계 수 | 1.0 = 밀도 일치 · >1 과분절 · <1 과소분절 |
| **purity** | 예측 구간이 gold 구간 하나에 얼마나 순수하게 담기나 | **과소분절에 벌점.** 🔴 잘게 쪼갤수록 자동으로 올라간다 — **단독 인용 금지** |
| **coverage** | gold 구간이 예측 구간 하나에 얼마나 덮이나 | **과분절에 벌점** |
| **F(p,c)** | purity·coverage 조화평균 | purity 단독의 착시를 즉시 드러낸다 |
| **L1** | P(경계\|예측) / P(경계) = 표준 lift | **<1.0 이면 역신호** — 찍은 자리가 오히려 경계일 확률이 낮다 |

### 🔴 우리 방법은 작동점 2종을 **나란히** 보고한다

| 접미 없음 (`M5`·`M4`·`M1-CosDrift`) | `-adaptive` |
|---|---|
| 고정분위수 **r=0.0642** + 구 체크포인트 | 적응 임계 **μ+1.0σ** + 동결 체크포인트 |

🔴 선택셋은 superseg/**validation**. test 아님, dev-3 아님.

dev-3 의 devbest 값 0.2919 도 무경계 하한(0.2790) 바로 위다. 표 기본은 원 repo 관행대로
**최종 체크포인트**를 유지한다.

## 3. 해석

### 3.1 서사에서 M5 가 1위, 그리고 **무경계 하한이 진짜 기준선이다**
dev-3 는 경계율 6.57% 로 매우 희소하다. 그래서 **아무 경계도 안 찍는 자명한 방법이 0.2790** 을
받는다. 이 선을 넘지 못한 방법은 **정보를 전혀 못 준 것**이다:
- 넘음 — M5(+0.140), M4(+0.107), SeCom-stateful(+0.090), M1(+0.054), TextTiling(+0.042)
- **못 넘음 — SeCom 무상태(+0.011), CSM(+0.009), RoBERTa(+0.001), GraphSeg(−0.058), GreedySeg(−0.080)**

GraphSeg·GreedySeg·CSM 은 285·206·194 개를 찍어 gold 66 대비 **3~4배 과분절**했다. 이 셋은 대화의
발화 단위(짧고 화자 교대가 신호)를 전제하는데, dev-3 는 화자도 턴도 없는 연속 산문이라
**국소 유사도가 항상 높아 임계가 무너진다**. 즉 이 점수는 "이 baseline 이 나쁘다"가 아니라
**"대화용 무감독 신호가 서사로 전이되지 않는다"**로 읽어야 한다.

### 3.2 LLM 에게 자기 경계를 보여주니 +0.079
같은 gpt-4o·같은 full-past·같은 기준 문구인데 **자기가 이미 확정한 분절을 문맥에 넣는 것만으로**
0.2899 → **0.3689**(ΔScore +0.0790). 이유는 경계 수에 그대로 보인다: **166 → 56**(gold 66).

무상태판은 매 문장을 독립 판정하므로 *"이 문서에 경계가 대략 몇 개여야 하는가"* 감각이 없어
2.5배 과분절했다. stateful 판은 "방금 경계를 찍었다 / 현 세그먼트가 N문장째다"를 알기 때문에
개수를 스스로 보정한다. **경계 개수 자가결정은 LLM 에게도 어려운 문제이며, 그 능력은
프롬프트가 상태를 주느냐에 달려 있다** — deployable 규약이 왜 중요한지의 직접 증거다.

다만 **F1 은 0.152 → 0.155 로 거의 그대로다.** 이득의 대부분은 Pk(0.491→0.375)·WD(0.653→0.459),
즉 **과분절 벌점 감소**에서 나왔지 *경계를 더 잘 맞춰서*가 아니다. LLM 은 여전히 **어디가**
경계인지는 잘 모른다 — 그래서 M5(F1 0.280)와의 격차 0.050 은 주로 F1 격차다.

### 3.3 대화(DTS-3)에서 M5 가 밀리는 것은 **알려진 원인이 있다 — 임계 도메인 불일치**
M5/M4/M1 은 경계율 **r = 0.0642** 를 서사 앵커에서 동결해 쓴다. 그런데 DTS 의 gold 경계율은
**14.8~25.1%** 로 2~4배다. 그래서 tiage 에서 M5 는 100개만 찍고 gold 는 315개다 — **구조적 과소분절**.
이 조건에서 나온 대화 점수는 "M5 가 대화를 못 한다"의 증거가 **아니라**, 우리가 서사에서 동결한
밀도 규칙을 대화에 그대로 들고 갔다는 사실의 결과다. 대화용 밀도를 대화 dev 에서 다시 동결하면
달라질 것이나, **그건 이 패스의 범위가 아니다**(별도 dev 필요, test 재선택 금지).

한편 **M1-CosDrift 가 tiage·dialseg711 에서 M5 를 크게 이긴다**(0.392 vs 0.315, 0.522 vs 0.383).
M1 은 학습이 없는 순수 코사인 드리프트라 도메인 편향이 없다. **M5 의 이득은 "서사 앵커로 학습한
것"에서 오고, 같은 이유로 도메인을 벗어나면 그 이득이 사라지거나 역전된다.** 이것이 이 실험이
준 가장 중요한 정보다.

### 3.4 superseg 에서는 전부경계 하한(0.3213)이 대부분을 이긴다
superseg 는 경계율 25.1% 로 조밀해 **전부 1 로 찍는 자명한 방법이 0.3213** 이다.
이를 넘은 것은 M5(0.3379)·M4(0.3339)·GraphSeg(0.3303)·CSM(0.3268) 뿐이고 격차는 0.017 이하다.
**superseg 의 무감독 결과는 사실상 아무 방법도 유의미하게 이기지 못한 것으로 읽어야 한다.**
(RoBERTa 0.7501 은 in-domain supervised 라 다른 층위다.)

### 3.5 노이즈 폭
D-B30 의 seed std(M5 0.0037 · M4 0.0072)를 기준으로 하면 dev-3 상위권의 차이는
M5−M4 = 0.033(seed-0), 3-seed 로는 0.0248 — **std 의 3~6배**로 노이즈 밖이다.
M5−SeCom-stateful = 0.050, M5−TextTiling = 0.098 도 마찬가지다.
반면 **superseg 의 M5−M4 = 0.004, M5−GraphSeg = 0.008 은 seed 노이즈 안**이라 순위를 주장할 수 없다.

### 3.6 (A) vs (B) 브릿지
이 표에서 두 하네스 차이는 dev-3 전 방법 **|A−B| ≤ 0.0035**, DTS-3 도 ≤ 0.016 으로 작다.
§1.7 에서 관측된 0.045 는 **집계 방식(전역 vs per-dialogue macro)이 문서 길이 분포와 상호작용할 때**
커지는 것이지 항상 그런 것은 아니다. 그래도 **주 결과는 (A) 로 고정**한다 — 사후에 유리한 쪽을
고르지 않기 위해서다.

### 3.7 supervised 2×2 — **도메인 붕괴는 대칭이다**
RoBERTa 는 이 표의 **유일한 supervised baseline**이자 M5 의 가장 가까운 peer다. 둘 다 지도학습이고
각자 자기 도메인(RoBERTa = 대화 gold, M5 = 서사 앵커)에서 학습됐다.

| | 서사 dev-3 | 대화 superseg |
|---|---|---|
| **M5** (서사 앵커 학습) | **0.4190** ← in-domain | 0.3379 (전부경계 하한 0.3213) |
| **RoBERTa** (대화 gold 학습) | **0.2799** ← 무경계 하한 0.2790 과 구별 불가 | **0.7501** ← in-domain |

- 대화에서 0.75 를 내는 supervised 모델이 **서사에서는 정보를 전혀 못 준다.** 경계를 151개
  찍었는데 gold 는 66개다(F1 0.145).
- 이것은 §3.3 에서 기록한 **우리 쪽 실패의 거울상**이다. 즉 "M5 는 도메인을 벗어나면 무너진다"는
  M5 고유의 결함이 아니라 **이 과제에서 학습 기반 분절기 일반의 성질**이다.
  🔴 다만 이 대칭이 M5 의 대화 실패를 **면책하지는 않는다** — M1(학습 없음)은 두 도메인 모두에서
  하한 위에 있고, tiage·dialseg711 에서 M5 를 이긴다.
- **논문에서 두 방향을 함께 보고한다.** 우리 쪽 붕괴만 적고 baseline 쪽을 안 적으면 불성실하다.

🔴 RoBERTa 의 하네스 (A) 수치는 원 REPORT 의 하네스 (C) 수치와 **다르다**
(tiage 0.4669 vs 0.5095, superseg 0.7501 vs 0.8167). window 규칙이 달라서다
— §1.7 의 원칙(하네스를 갈아끼우지 않는다)이 여기서도 실증됐다. **(C) 수치는 인용하지 않는다.**

### 3.8 CSM — 15시간 학습해서 얻은 결론은 "하한 근처"
CSM 은 이 실험에서 유일하게 **우리가 직접 처음부터 학습한** baseline 이다(체크포인트가 배포되지

- ⚠️ 이전 판 REPORT 에서 *"epoch 1 안에서 평평"* 이라 적은 관측은 전 일정에서도 대체로 유지된다

1. **배치 forward** — 원 구현이 배치당 96회의 batch-1 BERT forward(`CoherenceNet.forward` 의

2. **동적 패딩** — `attention_mask` 의 실제 최대 길이로 잘라 넣는다. CLS 만 읽으므로 등가.

3. **🔴 upstream 버그** — `validation()` 이 `model.eval()` 만 하고 `model.train()` 을 복원하지 않는데
   호출부는 **epoch 당 한 번만** `model.train()` 을 부른다. ⇒ step 1,000 의 첫 검증 이후
   **남은 24,000 step 이 전부 dropout off 로 학습**된다. 복원하도록 수정했다 —
   **baseline 을 강하게 만드는 방향**이라 불리하게 조작한 것이 아니다.
   ⚠️ 다만 이것은 **released `cpt_277000.pth` 를 만든 코드와 다른 코드**라는 뜻이다.

**⚠️ 재현성 결함 (미해결).** pseudo-sample 생성에 **시드가 없다** — 재시작할 때마다 표본이 달라진다
(888,560 / 889,137 / 885,498 관측). 우리가 추가한 `--data_seed` 는 split/sampler 만 덮는다.

#### 5.1.2 train.py 의 검증 지표는 분절 성능의 대리지표가 아니다
같은 구간에서 `validation_metric` 은 0.8506 → 0.7614 로 **−0.089 단조 하락**하는데 분절 Score 는
평평하다. 이유는 지표 구성에 있다 — `validation_metric` 은 (pos,neg1)·(pos,neg2)·**(neg1,neg2)**
세 쌍의 순위 정확도 평균인데, `data_utils.py` 상 `neg1` = **같은 대화**의 비인접·다른 dial-act 발화,
`neg2` = **다른 topic 대화**의 발화다. pos>neg1·pos>neg2 는 의미가 분명하지만 **neg1>neg2 는 약한
가정**이라, 모델이 pos 분리에 집중하며 neg1/neg2 구분을 놓으면 그 항만 0.5 쪽으로 떨어져 전체
지표가 내려간다. → 그래서 devbest 선택은 이 지표가 아니라 **분절 Score 로 직접** 했다.

#### 5.1.3 작성자 오류 기록 (제거 금지)
- 처음에 sparse subset(3k·5k·8k·10k·12k·14k) 6점만 보고 *"3k 저점 이후 단조 상승"* 이라고 적었다.
  18점을 전부 채우니 **평평한 잡음**이었다. 6점으로 추세를 말한 것이 잘못이다.
- 검증 지표 하락을 *"과적합"* 이라 했으나 **epoch 1 안에서는 88.5만 표본을 각각 한 번씩만 본다** —
  반복이 없어 고전적 과적합은 성립하지 않는다. 이 진단도 잘못이었다.
- CSM 의 α 가 "한 번도 설정된 적 없다"고 했으나 틀렸다. `2026-05-24_csm_online_delay2_fixed/REPORT.md`
  가 이미 α=1.0 을 썼고 `outputs/reports/dts_result.md` 에 완료된 CSM-Style 행이 있다.
- **작동점 탐색을 앵커 코퍼스에서 한 번 돌렸다.** 앵커에는 인간 경계 라벨이 없다(§1.5).
  산출 전량 폐기 + 코드 경로 차단으로 처리했다.

### 5.2 dev-3 는 문서 3편이다
전이는 1,005개지만 **문서 단위 n = 3**. Score 는 per-dialogue 평균이므로 실질 표본이 3이다.
문서별 경계 밀도 편차도 크다. 여기서 나온 순위는 **탐색적**이며, 봉인 시험지로 확인되지 않았다.
시험지 유효 n≈1 문제(D-M13③)도 아직 열려 있다.

### 5.3 이 실험 중 발생한 사고 (기록)
- `baseline_compare.py` 가 `results.json` 을 **통째로 덮어쓰고** 있었다. 03:04 DTS 실행이
  02:29 dev-3 결과를 지웠다. → 누적 병합으로 패치했고, **예측 덤프가 있어 재채점으로 복구**했다
  (복구값이 원 로그와 완전 일치 확인). 예측을 원자료로 두는 규칙이 실제로 사고를 막았다.
- CSM 학습이 146 step 에서 죽어 있었다(세션 종료에 딸려 사망). `setsid nohup … & disown`
  으로 완전 분리해 재기동. 이후 DDP 전환 시 `find_unused_parameters=True` 필요
  (BERT pooler 가 loss 에 안 쓰임).
- GraphSeg 는 NLTK 리소스 4종(`stopwords`/`punkt`/`punkt_tab`/`brown`) 과
  `averaged_perceptron_tagger_eng` 가 순차적으로 없어 계속 죽었다. 전부 설치해 해소.
  GloVe 990 MB 도 Stanford 에서 직접 받아야 했다.

### 5.4 baseline 을 스트리밍으로 바꾼 것 자체가 변형이다
TextTiling·GraphSeg·GreedySeg·CSM 모두 **원논문은 오프라인**(전 문서 depth score + 전역 임계,
CSM 은 dev 에서 α 탐색까지). 온라인 비교를 하려면 스트리밍화가 불가피하지만, 그 결과 이 점수는
**원논문 성능이 아니다**. 원논문 수치와 나란히 두면 안 된다(제3의 하네스 문제와 같은 계열).
스트리밍 적응 노브(윈도 D, delay 2, warmup, min_gap)는 우리가 정한 것이다. §1.5 에서 이 중
탐색 가능한 것은 선택셋에서 동결했지만, **"스트리밍화 자체"의 손실은 측정하지 않았다.**

### 5.5 SeCom 프롬프트는 원문이 아니라 도메인 적응판이다
SeCom 원문은 *"multi-turn **conversation**"* · *"**turn** … by one **speaker**"* 로 쓰여 있는데
dev-3 는 화자도 턴도 없는 서사 산문이다. 원문 그대로 쓰면 LLM 이 *대화적* 화제전환을 찾게 되어
**SeCom 에 불리한 허수아비**가 된다. 그래서 **기준·출력형식·요구사항은 한 글자도 안 바꾸고
도메인 명사만 교체**(conversation→narrative, turn→sentence, speaker 제거)했다.
그래도 이것은 **SeCom 원문 성능이 아니다.** stateful 판은 한 걸음 더 나간 **우리 창작 확장**이다.
LLM 도 gpt-4o 1종·1 draw 뿐이라 모델·seed 변동을 모른다.

### 5.6 M5/M4 는 seed 0 단일
§1.8 대로 이 표는 seed 0 이다. M4 seed-0(0.3861)은 3-seed 평균(0.3944)보다 낮아
**이 표만 보면 M5−M4 격차가 부풀려 보인다.** 격차 주장은 3-seed 값(+0.0248)으로 한다.

### 5.7 M5/M4/M1 의 turn 단위 지연 미측정
RQ2(지연)는 사용자 지시로 최후순위라 배치 추론으로 돌렸고, baseline 만 ms/turn 이 있다.
**현재 표의 지연 열로 우리 방법과 baseline 을 비교할 수 없다.**

### 5.8 앵커 라벨 노이즈 상한
M5/M4 학습 앵커는 자기일치도 **S_self 0.659** 로, 이것이 성능 상한 요인이다. 또 앵커는
k=1 단일 draw 이며 재실행 변동의 계통성은 상한만 측정됐다(별도 REPORT). 이 표의 절대값은
그 노이즈 위에 있다.

### 5.9 RoBERTa 4-seed — 재현은 됐으나 **zero-shot 분산이 크다**
표에 넣지 않는 **하네스 (C)** 수치다. 논문 대조 전용이며 §2 의 표와 섞지 않는다.
seed 42·43·44·45, 나머지 조건 동일.

| 평가셋 | 우리 4-seed | 범위 | 논문 Table 3 | Δ |
|---|---|---|---|---|
| superseg (in-domain) | **0.8170 ± 0.0010** | 0.8158~0.8182 | 0.798 | +0.019 |

### 5.10 CSM devbest 행은 선택셋이 하나뿐이다
§2.3 의 devbest 는 superseg/validation **앞 60대화**(792 turn · gold 159)에서 골랐다. 문서 60편은
작은 선택셋이고, 그 한 셋에서 고른 체크포인트를 네 데이터셋 전부에 쓴다. 서사(dev-3)용 체크포인트를
따로 고르지 않은 이유는 **dev-3 를 체크포인트 선택에 쓰면 dev-3 결과가 선택-오염**되기 때문이다.
즉 CSM 은 서사에서 **선택 이점 없이** 평가받는다 — 이는 CSM 에 불리한 방향이며 그대로 둔다.
