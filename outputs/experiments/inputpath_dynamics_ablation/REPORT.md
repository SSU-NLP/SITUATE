# D-B33 — 입력경로 × dynamics 2×2 분해: **분리의 이득은 전부 입력경로에서 온다**

> 🔒 **결론 한 줄**: 슬롯을 5개로 두는 것만으로는 아무 일도 일어나지 않는다. **입력 경로를 축별로
> 분리해야** 축이 분리되고(누출 +0.203 → +0.047) 분절 성능도 따라온다. 공유 투영 한 벡터로
> 표현하면 **5슬롯이어도 단일슬롯(M4)과 사실상 같아진다.** dynamics 분리(M5 vs M6)는 **무영향**.

---

## 1. 실험 setup

### 목적
`M5 − M4` 는 세 가지가 한꺼번에 바뀐 결과였다 — ①입력경로 분리(축별 extractor E_k) ②상태 분리
(5슬롯) ③dynamics 분리(축별 f_k). *"분리가 기여한다"* 까지만 말할 수 있었고 **어디서 오는지는
몰랐다.** ①과 ③을 각각 떼어내 분해한다.

사용자 질문 *"SEM 처럼 구조화된 스키마로 **하나의 벡터**로 표현하는 것도 해봤나?"* 에 대한 직접
응답이기도 하다.

🔴 **선행 관찰이 있다 — 이 라운드는 "첫 관찰"이 아니라 "확인 + 정량화"다** (D-B17 원장 §① 정정).
Phase 2(2026-07-15)에서 이미 *"v1(공유 입력) = 붕괴"* 가 기록돼 있었다: 모든 슬롯이 같은 **full
768D `z_t`** 를 보는 naive EntNet keyed slots 에서 **모든 슬롯이 모든 축을 동일 디코딩 → M5 ≈ M4
(0/5 분리)**, 그 진단 위에 codex 가 D1(축별 extractor 라우팅)을 도입했다. 본 라운드가 **새로 더한
것**은 넷이다:
1. **규모** — 10편(그중 7편이 오염된 Tier2) → **10,598편 청정 앵커**(900배), **3 seed**
2. **성능 비용의 정량화** — 선행 관찰은 프로브(축 분리)뿐이었고 **분절 Score 손실은 잰 적이 없다**
3. **용량 교란 배제** — 선행 v1 은 full 768D 였다. 여기서는 폭을 **40(=D1 총 입력폭 매칭)/128** 로
   좁혀, 붕괴가 *용량 과잉* 때문이 아니라 **라우팅 부재** 때문임을 가른다
4. **dynamics 축의 분리** — ③(축별 f_k)의 기여를 따로 뗀다(M6). 원장 3회 미해결 항목

⚠️ **`d1=False`(공유 투영)의 정확한 의미**: 벡터를 5블록으로 쪼개는 게 아니라, 공유 투영 `proj(z)`
**한 벡터가 5슬롯 전부에 브로드캐스트**된다. 슬롯은 key 와 자기 상태(EntNet 재귀)로만 갈라진다
⇒ *"표현은 하나의 벡터, 스키마 구조는 슬롯 상태·dynamics 에만"* = SEM 원안에 가장 가까운 대조군.

## 3. 해석

**① M5−M4 이득의 실질 전부가 입력경로 분리에서 온다.**
M5 → M4 의 손실은 online μ+1σ 기준 −0.0394. 입력경로만 공유로 바꾼 셀의 손실은 **−0.0365** —
**M4 와 거의 같다.** 즉 슬롯을 5개로 유지하고 축별 dynamics 를 유지해도, **입력이 하나의 벡터면
단일슬롯과 사실상 구별되지 않는다.** 상태 분리(5슬롯)와 dynamics 분리는 그 자체로 이득을 만들지
않는다.

**② 프로브가 그 기제를 정확히 설명한다 — 그리고 Phase 2 의 v1 붕괴를 900배 규모에서 확인한다.**
공유입력 셀의 축 얽힘(+0.2029/+0.2070)이 단일슬롯 M4(+0.2117)와 **거의 동일**하다.
선행 관찰(10편·1 run·full 768D 공유)에서 *"슬롯 = 중복 사본, M5 ≈ M4 (0/5 분리)"* 였던 것이,
**10,598편 청정 앵커 · 3 seed · 좁은 공유폭(40/128)** 에서도 그대로다 ⇒ **용량 과잉 탓이 아니다.** 키가 다르고 상태가 5개여도 **같은 입력을 보면 같은 것을 배운다.**
EISM 의 구조적 주장("지표들이 **분리되어** 추적된다")을 계산적으로 성립시키는 것은 슬롯 구조가
아니라 **입력 경로의 분리**다. Locatello 2019 불가능 정리의 실증이 한 겹 더 구체화된 셈이다 —
약한 지도(anchor)만으로는 부족하고, **정보 경로 자체를 갈라줘야** 한다.

**③ dynamics 분리는 무영향 — 그리고 이전의 "M6 > M5" 는 재현되지 않았다.**
M6 는 3 규칙 중 2 규칙에서 미세 우세, 1 규칙에서 열세 → 사전 규칙대로 **구별되지 않음**. 프로브도
동일(+0.0444 vs +0.0469). ⇒ **registry §3 의 M5/M6 구분은 성능·표현 어느 쪽에서도 근거가 없다.**
D-B17 이 1 seed 로 관찰한 *"M6(0.4395) > M5(0.4108)"* 는 **3 seed 로 재현되지 않았다** —
원장에 3회 미해결로 남아 있던 "M6 다중 seed" 항목의 답이며, **1 seed 관찰을 방향 주장으로 쓰면
안 된다는 사례**로 기록한다.

**④ 용량이 아니라 라우팅이다 (단, 부분적으로 용량도 관여).**
공유 투영 폭을 40→128 로 3.2배 키우면 격차가 −0.0365 → −0.0190 으로 **줄지만 사라지지 않는다.**
AUC 는 오히려 공유입력128 이 최고(0.7069)다. ⇒ 주 요인은 라우팅이되, 입력폭도 일부 기여한다.
D-B30 H묶음(bottleneck 8→32 평평)과 모순되지 않는다 — 거기서 바꾼 건 **축별** 폭이었다.

**⑤ AUC 는 전 셀 ±0.007 안이다.** 연속 점수의 **순위력 자체는 차이가 없고**, 차이는 임계 규칙과의
상호작용에서 나온다. 즉 공유입력 모델은 "어느 전이가 경계인지"를 못 맞추는 게 아니라 **점수 분포의
모양이 달라 같은 규칙 아래서 더 나쁜 경계 집합을 낸다.**

**⑤b 🔴 결론에 불리한 사실 — oracle 개수를 주면 순위가 뒤집힌다.**
gold 밀도 matched(문서별 gold 경계 **개수**를 주고 상위 n 개만 예측) 열에서는 **공유입력40×공유dyn
이 0.4762 로 1위, M5 가 0.4519 로 꼴찌**다. 즉 *"공유입력이 열세"* 는 **deployable 규칙 아래에서만
성립**하며, 개수가 맞춰지면 성립하지 않는다. AUC 가 전 셀 ±0.007 인 것과 일관된다.
⇒ **결론의 정확한 범위**: 입력경로 분리가 주는 것은 *"경계 후보를 더 잘 순위화한다"* 가 **아니라**
*"점수 분포가 임계 규칙과 더 잘 맞물린다"* 이다. 이 구분을 논문에 흐리지 않는다.
(⚠️ oracle 열은 개수 누출이므로 성능 주장에 쓰지 않는다 — CLAUDE.md. 여기서는 **우리 결론의
한계를 드러내는 용도**로만 인용한다.)

**⑤c 절대 Score 의 위치 — 무예측 하한 0.2790 과 비교.**
otsu 는 전 셀 0.2642~0.2837 로 **하한 근처이거나 그 아래**다(408개 예측). 하한을 뚜렷이 넘는
deployable 규칙은 μ+1σ 계열뿐이고 그것도 0.319~0.373 으로, 폐기된 r=0.0642 가 내던 **0.4191 보다
0.05~0.10 낮다**. oracle 개수를 주면 0.45~0.48 로 뛴다. ⇒ **지금 잃고 있는 것은 순위력이 아니라
개수 제어다**(⑥ 과 같은 결론에 두 경로로 도달).

**⑥ 임계 사전을 제거하니 전 셀이 2.4~6배 과분절한다** (160~408 vs gold 66). 이는 셀 간 비교를
무효화하지는 않지만(전 셀 동일 규칙) **절대 Score 를 크게 눌러 놓는다**. 그리고 이것은 D-B28 에서
스위칭 층이 실패한 원인(*"문서 전체의 경계 총량을 제어하는 항이 없다"*, 184개 예측)과 **같은 병**
이다 ⇒ 이 모델에는 경계 **개수**를 스스로 누르는 메커니즘이 없고, 폐기된 r=0.0642 가 그 자리를
대신 메우고 있었다.

## 5. 한계 / 검증 미해결 (제거 금지)

1. **dev-3 는 3편이다.** pieman 선택압 9회 누적. **절대 Score 를 성능으로 인용하지 않는다** —
   셀 간 Δ 와 방향만 읽었다. 시험지는 봉인 유지.
2. **monkey 에서 방향이 뒤집힌다.** 공유입력·M4 가 monkey 에서 오히려 낫다(0.2880~0.3085 vs
   M5 0.2756). 판정은 3편 중 2편(pieman·tunnel) 기준으로 통과했지만 **일관되지 않다.** D-B17 에서
   관찰된 *"이득이 pieman 에 몰린다"* 패턴이 여전하다. monkey 는 D-B31 에서도 우리 방법이 약했던
   문서다(상황모델이 정지한 텍스트 — 이론의 경계조건 후보).
3. **임계 미보정 상태의 비교다.** 전 셀 2.4~6배 과분절 구간에서 잰 Δ 이므로, 개수가 제어된
   상태에서도 같은 순위가 유지되는지는 **미확인**.
4. **앵커 라벨 k=1**, S_self 0.659 = 도달 가능 상한. 프로브의 축 특화 수치도 이 라벨 기준이다.
5. **프로브는 seed 1 단일 seed** (셀당 1회). Score 는 3 seed 지만 프로브는 아니다.
6. **J_anchor 는 판정에서 뺐으나, 실측상 dev-3 와 6셀 전부에서 방향이 일치했다** (M5 0.4056 ≈
   M6 0.4058 > 공유입력128 0.4030 > 공유입력40 0.3993 ≈ M4 0.3992). 이는 앵커 대리지표가
   임의적이지 않았음을 시사하지만, **순환 문제(의사-gold = 폐기된 t\*=3)는 그대로다.** 사실만
   기록하고 판정에는 쓰지 않았다.
7. **공유입력 셀의 "표현이 하나의 벡터"는 입력 단계에서만 참이다.** 슬롯 상태는 여전히 5×128 로
   유지된다. *완전한* 단일 상태 벡터는 M4(단일슬롯)이며, 그것도 함께 열세였다.
